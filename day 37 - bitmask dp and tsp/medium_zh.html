Day 37 — 狀態壓縮 DP 與 Held-Karp：用一個整數當集合索引，精確解出 TSP

程式碼：day 37 on GitHub

100 Days of Python - day 37

我以前寫過一支路線最佳化的程式，跑出來的數字比司機實際上跑得出來的成績還要低 25% 左右。它不會爆掉、不會警告，而且每次跑都穩定給同一個數字。我花了兩天才發現：我的 DP 狀態少了一個欄位，而我寫出來的那段遞迴其實完全正確——只是它在解另一個問題。

今天就是在講這個 bug。

從 Day 33 到 Day 36，DP 表格的索引一直在換形狀：前綴長度、剩餘容量、一段區間、一棵子樹。今天它變成一個集合。大約二十個元素以內的集合可以塞進一個整數裡，一個元素一個 bit，於是它可以直接拿來當陣列索引。一旦子問題可以用「哪些東西已經做完了」來編號，一整批看起來只能排列組合的問題就變成填表。

集合就是一個整數

整天的內容靠這五個操作撐起來：

def has(mask, i):    return (mask >> i) & 1
def add(mask, i):    return mask | (1 << i)
def remove(mask, i): return mask & ~(1 << i)
def members(mask):   return [i for i in range(mask.bit_length()) if mask >> i & 1]
def popcount(mask):  return bin(mask).count('1')

有兩個運算子優先順序的細節值得講清楚。在 C 裡面，mask & 1 == 0 會被解析成 mask & (1 == 0)，是經典的 bug；在 Python 裡 & 綁得比 == 還緊，所以這一行的意思跟看起來一樣。另外 ~mask 在 Python 裡是負數（~0b0101 是 -6），當成數值沒問題，但拿去當 list 索引就很危險，因為 dp[~mask] 會安靜地從另一頭讀。表格剛好有 2**n 格時，你要的補集是 mask ^ full。

列舉一個 mask 的所有子集是兩行慣用寫法，乍看像打錯字：

sub = mask
while True:
    yield sub
    if sub == 0:
        break
    sub = (sub - 1) & mask

減一會往低位的 0 借位，& mask 再把借來、但不屬於這個集合的位元丟掉。如果寫成 while sub: 而不是上面的 do-while，就會漏掉空集合——而空集合通常正是放 base case 的那一格。

還有，「對每個 mask，再對每個子 mask」的總工作量不是 4^n。每個元素只有三種身分：在子集裡、在 mask 裡但不在子集裡、或根本不在裡面，所以總和是 3^n：n = 10 時是 59,049，不是 1,048,576。

這一次填表順序是免費的

Day 36 的全部難處都在填表順序：區間 DP 一定要照長度由小到大填，直覺寫下去的 for i: for j: 會去讀還沒寫過的格子。狀態壓縮 DP 直接把這件事送給你。mask | (1 << nxt) 的數值一定大於 mask，因為 nxt 本來不在 mask 裡；所以單純一句 for mask in range(1 << n) 永遠不會讀到空格子，不管轉移式長什麼樣。

也就是說，今天的難處完全不在順序，而在狀態本身。

Held-Karp

題目是台灣的八個停靠點——台北、新竹、台中、日月潭、台南、高雄、台東、花蓮——串成一條封閉環線。總共有 5,040 種走法，暴力法全部檢查一遍，答案是 689 km。

Held-Karp 的表格索引是一組：走過哪些城市，以及現在站在哪一個。

dp[1 << 0][0] = 0
for mask in range(1 << n):
    for last in members(mask):
        if dp[mask][last] == INF:
            continue
        for nxt in range(n):
            if has(mask, nxt):
                continue
            nm = add(mask, nxt)
            cand = dp[mask][last] + D[last][nxt]
            if cand < dp[nm][nxt]:
                dp[nm][nxt] = cand
                parent[nm][nxt] = last
best = min(dp[full][last] + D[last][0] for last in range(1, n))

last 這個欄位就是整段的重點。兩條走法如果覆蓋同一組城市、又停在同一個城市，那麼對接下來的一切來說它們完全可以互換，所以只需要留便宜的那一條。五個城市、長度 4 的 24 條前綴會壓成 12 個狀態；一般情況就是 (n-1)! 條排列壓成 2^n · n 個狀態。

parent 是把一個數字變回行程表的東西。遞迴本身完全不需要它，所以它很常被省略，然後事後要補回來特別痛苦。

讓我花掉兩天的那個 bug

假設狀態只有 dp[mask]。遞迴照樣寫得出來、照樣會終止、照樣回傳一個數字。但既然不知道前一段停在哪裡，下一段唯一寫得出來的成本，就只剩「到最近的那個已走訪城市」的距離：

hop = min(D[i][nxt] for i in members(mask))
dp[mask | 1 << nxt] = min(dp[mask | 1 << nxt], dp[mask] + hop)

這不是一段壞掉的遞迴。它是另一個問題的正確遞迴：它把每個新城市接到最近的已走訪城市上，長出來的是一棵樹，不是一條環線。沒有任何人回家。

八城市的那組資料，它回傳 502 km。而同一組資料的最小生成樹重量也是 502 km——因為那就是它算出來的東西。這是 TSP 的經典下界：永遠比真正的最佳解 689 小，永遠看起來合理，而且永遠不會有人跳出來說話。

另一種錯法

乾脆不做 DP，每一步都挑最近的沒走過的城市。最近鄰居法只要 O(n²)，產生的是一條貨真價實的封閉環線，答案是 795 km——比最佳解貴 15.4%，而且看起來就像一份合理的行程表。

出事的只有一步。站在日月潭，最近的沒走過的城市是花蓮（74 km），比往南的台南（116 km）近。走過去之後，整個南部——台南、高雄、台東——只能之後再繞回來拿，而那趟繞路的代價遠超過現在省下的 42 km。貪心看不到這件事，因為它的狀態裡根本沒有「還剩哪些城市」。

這兩種錯誤剛好把正確答案夾在中間，所以值得一起記：樹永遠比最佳解小，貪心環線永遠比最佳解大，而且兩者都不丟例外。「它有跑完」不能當作 TSP 實作正確的證據。

複雜度，以及那道牆搬到哪裡

2^n · n² 仍然是指數。Held-Karp 沒有讓 TSP 變得可解，它只是把牆往後搬。這支模組實測：暴力法在 n = 8 是 8.6 ms、n = 9 是 98.8 ms、n = 10 是 890 ms；Held-Karp 在 n = 8 是 1.2 ms，n = 15 是 614 ms——而暴力法在 n = 15 大約要跑 42 小時。

超過大約二十個城市，表格本身就塞不進記憶體了，答案只能從別的地方來：放棄最佳性的啟發式方法，像是基因演算法或模擬退火；或是分支定界解法——而它用來剪枝的下界，正好就是上面那段「壞掉的」遞迴不小心算出來的東西。

LeetCode 847 - Shortest Path Visiting All Nodes（訪問所有節點的最短路徑）

題意。 給一張連通的無向圖，求出「每個節點至少走訪一次」的最短走法有多少條邊。起點終點都可以任選，節點和邊都可以重複走。

輸入／輸出。 graph 是相鄰串列，graph[i] 列出節點 i 的鄰居。回傳最短走法用到的邊數。

範例。 graph = [[1,2,3],[0],[0],[0]] 的答案是 4。節點 0 是接著三片葉子的中心，所以像 1 - 0 - 2 - 0 - 3 這樣走要四條邊，而中心必須被經過兩次。

限制。 n 最多 12，這就是全部的提示：2^12 · 12 個狀態很小，12! 不小。因為允許重走，所以這不是 Hamiltonian path 問題，而且每一步的成本固定是一條邊。

既然每條邊成本相同，這題是 BFS 而不是填表——但狀態就是今天的狀態：(走過哪些節點的 mask, 現在在哪個節點)。每個 i 都用 (1 << i, i) 當種子丟進 queue，因為任何節點都可以當起點，然後第一次看到 mask 滿了就停。唯一要寫對的是：visited 要記在 (mask, node) 這一對上，不是記在 node 上。記在 node 上的寫法，遇到必須繞回中心的圖就會給出太大的答案。

LeetCode 943 - Find the Shortest Superstring（最短超級字串）

題意。 把給定的所有字串排成一條字串，使每個輸入字串都是它的子字串，並且這條字串越短越好。最短答案有多個時回傳任何一個都可以。

輸入／輸出。 words 是一組字串；回傳一條字串。

範例。 words = ["catg","ctaagt","gcta","ttca","atgcatc"] 的其中一個最短答案是 gctaagttcatgcatc，16 個字元。五個輸入字串合計 25 個字元，而 gcta, ctaagt, ttca, catg, atgcatc 這個順序重疊掉了其中 9 個。

限制。 最多 12 個字串，每個最長 20 個字元，而且沒有任何一個字串是另一個的子字串——最後這一句才是讓「用某個順序接起來」變成完整搜尋空間的關鍵，而 12 又是 bitmask 的提示。

這題就是把 TSP 換兩個東西：距離換成重疊、min 換成 max。先算好 ov[a][b]，也就是 a 的尾巴已經替 b 的頭寫掉幾個字元，然後跑同一張 dp[mask][last]，改成最大化總重疊。最小化最終長度和最大化重疊是同一件事，因為輸入長度總和是常數。

陷阱在種子，而且它正好是 TSP 那件事的鏡像。環線裡任何城市都可以叫做起點，所以只種 dp[1][0] 是免費的；這一題求的是一條開放的鏈，第一個字是真的決定。只種一個起點照樣會得到一個合法的超級字串——以這組輸入來說是 catgcatcgctaagttca，18 個字元而不是 16。比較長、完全合法，而且小測資常常看不出來。

leetcode.com/problems/find-the-shortest-superstring

LeetCode 526 - Beautiful Arrangement（優美的排列）

題意。 數 1..n 的排列中，有多少個排列讓每個元素都跟它的位置相容：對每個 1 起算的位置 i，放在那裡的數字要能整除 i，或者 i 能整除那個數字。

輸入／輸出。 一個整數 n；回傳符合條件的排列數。

範例。 n = 2 的答案是 2。[1,2] 可以，因為 1 整除 1、2 整除 2；[2,1] 也可以，因為 2 被位置 1 整除、1 整除位置 2。

限制。 1 <= n <= 15。15 的階乘是 1.3 兆，2^15 · 15 大約五十萬。

這一題的狀態只有 mask——而這正是有趣的地方。popcount(mask) 本身已經說出現在要填第幾個位置，所以第二個欄位是多餘的：dp[mask] = sum(dp[拿掉 i 的 mask])，對每個跟位置 popcount(mask) 相容的 i 加總。這也正是 TSP 裡少掉的 last 這麼容易被忽略的原因：有時候那個額外欄位真的可以從 mask 推回來。每次該問的不是「這個狀態看起來夠小嗎」，而是「下一步的成本，只用狀態記得的東西寫得出來嗎」。

leetcode.com/problems/beautiful-arrangement

這件事之後會用在哪裡

同一張 (mask, last) 表格會在所有「一小組東西要決定順序」的地方再出現：指派問題、bitonic tour、少量活躍值的暫存器配置。而今天這兩個錯誤答案的壽命很長——生成樹下界正是分支定界 TSP 解法拿來剪枝的東西，最近鄰居法則是啟發式搜尋的標準起手式，然後那個搜尋接下來的時間，就花在修我們剛剛在日月潭看著它犯下的那個錯。
