Day 29 — 區間結構：Segment Tree 與 Fenwick Tree

程式碼：day 29 on GitHub

100 Days of Python - day 29

一個陣列，兩個操作：改一格，然後問某一段的總和。任何一邊挑最直覺的做法，另一邊就爛掉。

純陣列改一格是 O(1)，問一段是 O(n)。Prefix sum 陣列問一段是 O(1)，但改一格要 O(n) — 因為動到 a[2]，index 2 之後的每一個前綴和都失效了。一百萬個元素的話，前者每次查詢要加一百萬次，後者每次更新要重寫一百萬格。兩個剛好是彼此的鏡像，各自在一件事上完美、在另一件事上沒用。

今天整篇文章都在做同一件事：拒絕在這兩者之間選邊。昨天的平衡樹是讓一堆 key 保持好找，今天的結構是讓一堆區間的摘要保持好維護 — 問題不一樣，但形狀非常像。

Segment tree：把區間切成一整棵一整棵子樹

想法是先把所有「自然的區塊」的總和都算好 — 整個陣列、每一半、每四分之一，一路切到單一元素 — 之後任何查詢都只是把其中幾塊黏起來。

我實際會寫的是迭代版。它把整棵樹放在一個長度 2n 的平坦陣列裡：第 i 個葉子在 t[n + i]，節點 k 的父親是 k >> 1。沒有節點物件、沒有遞迴、沒有指標。

class SegmentTree:
    def __init__(self, data):
        self.n = len(data)
        self.t = [0] * (2 * self.n)
        self.t[self.n:] = data
        for k in range(self.n - 1, 0, -1):        # build bottom up
            self.t[k] = self.t[2 * k] + self.t[2 * k + 1]

    def update(self, i, value):
        k = i + self.n
        self.t[k] = value
        while k > 1:                               # walk up the parent chain
            k >>= 1
            self.t[k] = self.t[2 * k] + self.t[2 * k + 1]

    def query(self, l, r):                         # half open [l, r)
        res, l, r = 0, l + self.n, r + self.n
        while l < r:
            if l & 1: res += self.t[l]; l += 1     # l is a right child: take it
            if r & 1: r -= 1; res += self.t[r]     # r is a right child: take r-1
            l >>= 1; r >>= 1
        return res

兩個指標從葉子往上爬，只有當一個節點完全落在區間裡才把它收走，那兩個 & 1 判斷問的就是「我是不是一個突出來的邊角」。canonical_cover(16, 3, 13) 回傳 [5, 6, 19, 28] — 十個元素的查詢，只讀四個存好的和。

上界是 2·log2(n)，而理由短到可以直接記住：每一層最多只會有一個節點是左邊突出的邊角、一個是右邊突出的邊角，所以每層最多拿兩個。實測比上界寬鬆很多：n = 65536 平均 13.25 個節點（上界 32），n = 1000000 平均 17.03 個（上界 38）。

有一件事要先注意，因為文章最後會回來算帳：查詢從頭到尾只把互不相交的區塊合起來，一次減法都沒有。所以那個合併可以換成任何滿足結合律的運算 — sum、min、max、gcd、矩陣乘法 — 改兩行就好。

Lazy propagation：同一招，搬到更新這一邊

現在改成「把某一段的每個元素都加上 delta」。走到每一片葉子是 O(n)，等於白蓋這棵樹了。但查詢已經會把區間切成整棵子樹，而被整段蓋住的節點根本不用問小孩：它的總和就是加上 delta * width。

那就在那裡加完、留一張便條、然後停下來。

def _apply(self, k, delta, width):
    self.t[k] += delta * width          # this node's sum is now correct
    if k < self.size:
        self.lazy[k] += delta           # the children are owed the same delta

def _push(self, k, lo, hi):
    if self.lazy[k]:
        mid = (lo + hi) // 2
        self._apply(2 * k,     self.lazy[k], mid - lo + 1)
        self._apply(2 * k + 1, self.lazy[k], hi - mid)
        self.lazy[k] = 0

這裡的不變式值得講清楚，因為安全性全靠它：一個節點自己的總和永遠是正確的；它的小孩可能落後，落後多少就記在 lazy 裡。這筆帳由 _push 結清，而且只有真的有人要往下走的時候才結。

這是「延後做」不是「不做」，而且省下來的量不是邊際的。100000 個元素、2000 次隨機 range add：eager 版走了 100775266 個節點，lazy 版 116963 個，其中 42681 次 push down。862 倍。

而且那張便條不一定要是數字，它只要能疊加就好。「整段設成某個值」、「整段乘上某個係數」、「套一個仿射變換」都是合法的 tag — 這也是為什麼同一招會出現在區間排程、整棵子樹上色，以及任何「對一整個區域套一個運算子」的地方。

Fenwick tree：把樹丟掉，只留下位元

接著是另一個答案：一樣的複雜度，但完全沒有樹。

Peter Fenwick 1994 年的論文裡自己就把它叫做 binary indexed tree，所以是的，BIT 和 Fenwick tree 是同一個東西，同一篇討論裡兩個名字混著用很正常。它只存 n + 1 個數字、零個連結，整個設計就是一個式子：i & -i，也就是 i 的最低位元。

def prefix(self, i):                 # sum of a[0:i]
    s = 0
    while i > 0:
        s += self.t[i]
        i -= i & -i                  # strip the lowest set bit
    return s

def add(self, i, delta):             # a[i] += delta
    i += 1
    while i <= self.n:
        self.t[i] += delta
        i += i & -i                  # climb to the next responsible cell

t[i] 存的是以 i 結尾的 i & -i 個元素的總和。t[8] 蓋住 a[0:8]、t[12] 蓋住 a[8:12]、t[6] 蓋住 a[4:6]、t[7] 只蓋住 a[6:7]。這個階梯不是誰設計出來的排版，它就是二進位計數本身長出來的形狀。

prefix(13) 把 1101 的位元一顆一顆剝掉：13 → 12 → 8 → 0，一個 set bit 讀一次。add 則爬另一條互補的鏈。兩個迴圈最多跑 log2(n) 次，實際上通常更少 — n = 1000000 的 prefix 平均 9.88 步，最壞 19 步。

回報在記憶體和常數上。一百萬格 64-bit：迭代 segment tree 要 2n、遞迴版 4n、lazy 版 8n、Fenwick tree 只要 n + 1。20000 個元素、2000 組（更新 + 區間查詢）實測：Fenwick 22.5 ms、segment tree 44.0 ms、純陣列 87.4 ms、prefix sum 9068.1 ms。六行程式、lazy tree 四分之一的記憶體、最單純那棵樹兩倍的速度。

它能做的也不只前綴和，這部分知道的人反而不多。拿一個 BIT 蓋在差分陣列上，range add 就變成兩次點更新；拿兩個 BIT，就能同時支援 range add 與 range sum，靠的是 prefix(i) = B1.prefix(i) * i − B2.prefix(i) — lazy segment tree 的複雜度、四分之一的記憶體。至於 lower_bound（前綴和第一次達到某個目標的位置）就是在同一個陣列上做二進位跳躍，O(log n)，不用多開任何結構 — Fenwick tree 就是這樣變成一個加權抽樣器的。

BIT 做不到的事

那還留著 segment tree 幹嘛？

a = [5, 3, 8, 1]; a[3] = 9
real min          = 3
prefix-min BIT    = 1     # wrong - it never forgot the 1
min segment tree  = 3

BIT 的區間查詢一律是 range(l, r) = prefix(r) − prefix(l)。那個減號不是實作細節，它是對運算本身的要求：必須存在反元素。加法有，xor 有，min 沒有。一旦那個 1 被折進某一格，就沒有任何操作能把它拿出來 — 所以 prefix-min BIT 只支援值變小，值一變大它就會給你一個看起來很合理的錯答案，而且完全不會報錯。

Segment tree 從來不減。它只把互不相交的區塊合起來，所以唯一的要求是結合律，min、max、gcd、矩陣乘法原封不動全部可用。

這才是兩者真正的分界線，不是常數也不是記憶體：先問「這個運算能不能被減掉」。

LeetCode

307. Range Sum Query - Mutable 就是這個主題的標準題，它是故意設計成兩種天真解都活不下來的。兩種結構都幾行就寫完，但 BIT 版本藏了一個面試官在聽的細節：BIT 存的是差值不是值，所以「把 a[i] 設成 val」要寫成 add(i, val - a[i])，也就是你得自己另外留一份原陣列。漏掉這件事，整棵樹會慢慢歪掉而且永遠不報錯。另一個常見失分是區間慣例：LeetCode 的 sumRange 是閉區間，半開的 range_sum 要記得 r + 1。

315. Count of Smaller Numbers After Self 是值得背起來的轉換。先把值壓縮成 rank，然後從右往左掃，這樣「在我後面」就等於「我已經看過的」，BIT 當成一個計數直方圖用。每個元素只花一次 prefix(rank) 和一次 add。n = 4000 時大約比兩層迴圈快 30 倍。而「把統計問題轉成 prefix 查詢」這一招，逆序數對、滑動視窗排名、離線區間統計全部通用。

370. Range Addition 則是刻意放的反高潮。所有更新都發生在任何查詢之前，所以差分陣列 O(n + k) 已經最佳，樹一點忙都幫不上。

所以決策流程其實很短。先問：更新和查詢是交錯的嗎？不是的話，用 prefix sum 或差分陣列。是的話而且運算可以減，寫那六行的 Fenwick tree。是的話但運算不能減，才蓋 segment tree — 如果更新也是整段整段來，再給它 lazy tag。

之後會用到的地方

強化學習裡的 prioritized replay buffer 本質上就是一棵 sum tree：依照優先度比例抽樣，其實就是在前綴和結構上做 lower_bound，而優先度每次梯度更新都會變 — 天生就是「交錯」的那一類。從一個權重會動的 token 分布抽樣也是同一個操作。區間重疊查詢、掃描線、離線區間統計也都坐在這兩個結構其中之一上，而要選哪一個，還是回到那個關於反元素的問題。

LeetCode 307 - Range Sum Query - Mutable（區域和檢索 — 可修改）

題目。 針對一個整數陣列做一個 NumArray，支援兩種可以任意交錯的操作：update(index, val) 修改單一元素、sumRange(left, right) 回傳閉區間的總和。

輸入／輸出。 建構子吃 nums；update 無回傳值，sumRange 回傳整數。

範例。 nums = [1,3,5]：sumRange(0, 2) 是 9；執行 update(1, 2) 後陣列變成 [1,2,5]， sumRange(0, 2) 是 8。

限制。 1 <= len(nums) <= 3 * 10^4、-100 <= nums[i] <= 100，update 與 sumRange 合計 最多 3 * 10^4 次。兩個直覺解都會死：純陣列的 sumRange 是 O(n)，前綴和陣列的 update 是 O(n)。這正是 Fenwick tree 或 segment tree 存在的理由 —— 兩邊都 O(log n)。

LeetCode 315 - Count of Smaller Numbers After Self（計算右側小於當前元素的個數）

題目。 對每個位置 i，數出 nums[i] 右邊有幾個元素嚴格小於它，把這些數字組成陣列回傳。

輸入／輸出。 輸入 nums，輸出同長度的串列。

範例。 nums = [5,2,6,1] → [2,1,1,0]：5 的右邊有 2 和 1；2 的右邊有 1；6 的 右邊有 1；1 的右邊沒有東西。

限制。 1 <= len(nums) <= 10^5，數值在 [-10^4, 10^4]。雙層迴圈是 10^10 次運算，不可能過。 從右往左掃、同時把值插進以「數值」為索引的 Fenwick tree，可以做到 O(n log U)；用 merge sort 數 逆序對、或用支援 order statistic 的 skip list，也都到得了。

LeetCode 370 - Range Addition（區間加法）

題目。 一開始是長度 n、全為 0 的陣列，和一串更新，每一個形如 [start, end, inc]，意思是 「把索引 start 到 end（含兩端）的每個元素都加上 inc」。全部套用後回傳最終陣列。

輸入／輸出。 輸入 length 與 updates，輸出結果陣列。

範例。 length = 5、updates = [[1,3,2],[2,4,3],[0,2,-2]] → [-2,0,3,5,3]。

限制。 1 <= length <= 10^5、0 <= len(updates) <= 10^4，索引都在範圍內，-1000 <= inc <= 1000。老實地逐一套用是 O(length * updates)。改用差分陣列 —— 在 start 加上 inc、在 end + 1 減掉它，最後做一次前綴和 —— 每次更新就變成 O(1)；Fenwick tree 把同一個把戲推廣成 「區間更新 + 單點查詢」。
