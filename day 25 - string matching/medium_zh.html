100 Days of Python - day 25

在字串裡找子字串，大概是這整個系列最基本的問題，Python 直接一句 needle in haystack 就結束了。 我還是覺得它值得一天，因為兩個經典演算法 — KMP 和 Rabin-Karp — 講的其實不是字串，而是兩種 「不做多餘工作」的方式；而且它們都躲在 LLM 推論伺服器的實作裡，只是沒有掛上名字。其中一個，還連帶 牽出一個只有打開投機解碼才會出現的 bug。

昨天的 radix tree 是把共同前綴只存一次，今天則是反過來：怎麼把它找出來。

天真版的問題是「會忘記」

每個位置對齊一次，從頭比到尾。用 'a' * 40 + 'aaab' 去找 'aaab'，天真版要 164 次字元比較， KMP 只要 84 次。

重點不是這個比例，而是原因。看比對在位置 j 失敗的那一瞬間：程式其實剛剛證明了文字的最後 j 個 字元，就等於 pattern 的前 j 個字元。然後它把這個證明丟掉，往右挪一格，從 j = 0 重來。KMP 做的 所有事，都只是拒絕丟掉這個情報而已。

failure function 就是一張 border 表

字串的 border 是「同時是開頭也是結尾」的那一段。fail[i] 就是 pat[:i+1] 最長 border 的長度， 以 ababaca 為例，這張表是 [0, 0, 1, 2, 3, 0, 1]。

def build_failure(pat):
    fail = [0] * len(pat)
    k = 0                              # length of the current border
    for i in range(1, len(pat)):
        while k > 0 and pat[i] != pat[k]:
            k = fail[k - 1]            # fall back to a shorter border
        if pat[i] == pat[k]:
            k += 1
        fail[i] = k
    return fail

while 那一行就是整個演算法：長度 k 的 border 延伸不下去時，下一個候選不是 k - 1，而是 fail[k - 1] — 因為 pattern 比較短的 border，一定也是那個 border 的 border。k 每一輪最多加一， 所以往下掉的總次數不可能超過往上加的總次數，這就是為什麼裡面明明有兩層迴圈，建表卻是 O(m)。

有了這張表，搜尋只要掃一遍：

def kmp_search(text, pat):
    fail, j, hits = build_failure(pat), 0, []
    for i, ch in enumerate(text):      # i never goes backwards
        while j > 0 and ch != pat[j]:
            j = fail[j - 1]
        if ch == pat[j]:
            j += 1
        if j == len(pat):
            hits.append(i - len(pat) + 1)
            j = fail[j - 1]
    return hits

i 只會往前。這不是省幾個 cycle 的小把戲，而是改變了這個演算法能跑在什麼東西上：一段你回不去的 文字。一條 socket。一串 token。

被切成四段送進來的 stop string

每個生成請求都帶著 stop string — </s>、\n\nHuman:，或是應用自己定義的結束標記。伺服器必須在 還在把文字串流給使用者的同時偵測它，這就把兩種最直覺的寫法都排除了：等生成完再比對就不叫 streaming， 每產生一個 token 就重掃整段輸出則是平方複雜度。

一個 stop string 配一個 KMP 狀態就解決了：每個 pattern 只留一個整數，完全不需要記住已經送出的文字。 真正需要內化的是扣住不送（hold-back）這件事：

當比對長度是 3，那三個字元有可能是 stop string 的開頭，而送出去的文字收不回來，所以它們必須先扣著， 等下一段進來再說。餵進 ['The answer is 4', '2.<', '/s', '> and then some more']，依序送出 The answer is 4、送出 2. 但扣住 <、什麼都不送並扣住 <、/、s，然後停止。

sglang 在 schedule_batch.py 裡解同一個問題，有趣的是它沒有用 KMP： check_match_stop_str_prefix 直接試每一種後綴長度去比切片，是 O(m²)。這個選擇完全合理，因為它 會先把 tail 裁到 stop_str_max_len + 1 個字元。把輸入長度界住，是「換更好的演算法」以外一個同樣 正當的解法 — 前提是那個界要是對的。而這正好帶出接下來的 bug。

token 不是字元

stop string 是用字元寫的，模型吐出來的是 token，而 token 的邊界跟人打出來的字串一點關係都沒有。 在我的玩具 vocabulary 裡，stop string ]] 的第一個 ] 藏在 token " 42]" 裡面，第二個才是獨立 的一個 token。

所以每一步都得把最後幾個 token 解碼回文字再找。問題是「幾個」才安全？每步只接受一個 token 的時候， stop_max_len + 1 個字元就夠了：剛完成的 stop string 一定結束在剛剛加進去的那個 token 上。 投機解碼一開，這個前提就破了。

一次落地好幾個 token，stop string 可能在這一批的中間就完成，整個落在固定視窗的後面。我把同一個 例子跑兩種模式：每步 1 個 token 在第 5 個 token 抓到 ]]；每步 4 個 token 配同樣的固定視窗， 從頭到尾都沒抓到。sglang 的修法是 _stop_match_tail_len：

min(stop_str_max_len + 1 + max(new_accepted_len - 1, 0), len(output_ids))

多開 accepted - 1 才把整批拉回視野裡。用字元數去當 token 數的上界，在保守的方向上是安全的，因為 一個 token 至少解出一個字元。而且抓到只做完一半 — 請求的結束長度是用 token 算的，所以 _locate_str_stop_finished_len 會把視窗的前綴一段一段解碼回文字，直到 stop 出現，回答「第 5 個 token 收工，保留 The answer is 42」。比對活在字元空間，記帳活在 token 空間，兩邊只能靠解碼接起來。

這種 bug 特別值得研究：出錯的不是某一行寫錯，而是某一行的前提，因為別的地方打開了一個功能而悄悄不成立了。

Rabin-Karp：先比指紋，再比字串

另一個經典做法換了個問法。把目前的視窗當成一個 base-256 的數字取大質數的 mod，往右滾一格只要一次乘加：

ht = ((ht - ord(text[i]) * high) * base + ord(text[i + m])) % mod

指紋不同就一定不是；指紋相同只是可能是 — 所以每一次指紋命中之後，都要真的比一次字串。

那一行 verify 是演算法的一部分，不是防禦性寫法。把 mod 設成 101，aah 和 aca 的指紋都是 41， 在 xaahy 裡找 aca 會得到一次指紋命中、一次驗證後打回、零個回報結果。把 verify 拿掉，程式不會當掉， 只會安靜地回報一個根本不存在的位置。在 KMP 擅長的題型上，Rabin-Karp 沒有任何優勢；它真正的主場是 一次找 k 個同長度的 pattern — 測一個指紋和測一整個 set 的成本是一樣的。

另一種指紋：一種你「驗不了」的 hash

sglang 幫每一頁 KV cache 取的名字，是一個鏈式 SHA-256（mem_cache/utils.py）：每一頁的 digest 都把前一頁的 digest 一起餵進去，所以這個 id 代表的是從開頭到這裡的整段前綴，而不是它裝的那四個 token。

兩個共用 system prompt 的請求，共用的那幾頁會拿到一模一樣的 id，並且在 token 分岔的地方立刻分開。 而裝著同樣四個 token、但前面歷史不同的一頁，會拿到不同的 id — 這是刻意的，因為 attention 的 K/V 取決於整段前綴。

現在把它放到 Rabin-Karp 旁邊看：這裡沒有 verify 這一步，而且做不到。 要拿來比對的那些 token 早就 不在手上了，命中的當下伺服器只握著一個 id。整個正確性完全押在 SHA-256 不會碰撞上。換一個便宜的 hash， 碰撞的後果不是變慢，而是一個請求讀到另一個請求的 KV cache。挑 hash 的時候，「事後能不能驗」比 「快不快」重要得多。

LeetCode

28（strStr） 就是演算法本身。真正值得準備的是 459 和 214 這一對，因為它們都不是「搜尋」， 而是直接用 border 這個量。

def repeated_substring_pattern(s):          # LC 459
    n = len(s)
    b = build_failure(s)[-1]                # longest border
    return b > 0 and n % (n - b) == 0       # n - b is the period

def shortest_palindrome(s):                 # LC 214
    if not s:
        return s
    probe = s + "\x00" + s[::-1]
    k = build_failure(probe)[-1]            # longest palindromic prefix
    return s[k:][::-1] + s

如果 s 最長的 border 是 b，那把 s 往右挪 n - b 格會和自己疊合，所以 n - b 是一個週期， 而 s 是重複拼出來的，若且唯若這個週期整除 n。b > 0 這個守門就是面試的陷阱：少了它，abc 會被 算成「自己重複一次」。214 則是：s 最長的回文前綴，就是「s 的前綴同時也是 reversed(s) 的後綴」， 所以對 s + 分隔符 + reversed(s) 做一次 failure function 就得到答案 — 分隔符必須是兩邊都不會出現的 字元，否則 border 會跨過接縫、算出過長的結果。LC 1044 則是 Rabin-Karp 那一面：對長度二分，每個候選 用 rolling hash 加驗證。

這些東西之後會用在哪

border 和 rolling hash 是這一段字串主題底下的地基：suffix array 和 Aho-Corasick 把「我已經對上多少」 推廣到同時比對很多個 pattern，MinHash 則是把「比指紋不比內容」從相等推廣到相似。BM25 和 hybrid retrieval 的 shingling 也是同一個 rolling hash。而上面那兩個推論伺服器的機制 — stop string 的視窗 和鏈式 page id — 正是我想把「比對」和「hash」放在同一天講的原因：一個可以事後驗證自己的猜測，另一個 在結構上就驗不了，而這個差別直接決定了你能挑什麼 hash。

LeetCode 28 - Find the Index of the First Occurrence in a String（找出字串中第一個匹配項的下標）

題目。 給兩個字串 haystack 與 needle，回傳 needle 在 haystack 中第一次出現的索引； 沒出現就回傳 -1。

輸入／輸出。 輸入兩個字串，輸出一個整數。

範例。 haystack = "sadbutsad"、needle = "sad" → 0（索引 6 也有一個，但我們要第一個）。 haystack = "leetcode"、needle = "leeto" → -1。

限制。 1 <= len(haystack), len(needle) <= 10^4，都是小寫英文字母。這個規模用最樸素的雙層 迴圈就會過 —— 所以它剛好是拿來跟 KMP *比較*的好題目，而不是被逼著寫 KMP 的題目。

LeetCode 214 - Shortest Palindrome（最短回文串）

題目。 你只能在字串的前面加字元，請回傳這樣能做出來的最短回文。

輸入／輸出。 輸入一個字串，輸出一個字串。

範例。 s = "aacecaaa" → "aaacecaaa"（加了一個 a）；s = "abcd" → "dcbabcd"（加了 三個字元）。

限制。 0 <= len(s) <= 5 * 10^4，小寫英文字母。關鍵在於換句話說：前面加得越少越好，等價於 找出 s 的*最長回文前綴*；而只要對 s + '#' + reversed(s) 跑一次 KMP，這就變成一個 prefix function 的問題。

leetcode.com/problems/shortest-palindrome

LeetCode 459 - Repeated Substring Pattern（重複的子字串）

題目。 判斷這個字串能不能由它的某個真子字串重複兩次以上接起來而成。

輸入／輸出。 輸入一個字串，輸出布林值。

範例。 "abab" → True（"ab" 兩次）；"aba" → False；"abcabcabcabc" → True （"abc" 四次，或 "abcabc" 兩次）。

限制。 1 <= len(s) <= 10^4，小寫英文字母。一行解 s in (s + s)[1:-1] 很可愛，但能推廣的是 KMP 的說法：字串是週期的，等價於 n - failure[n-1] 整除 n 且小於 n。

leetcode.com/problems/repeated-substring-pattern

LeetCode 1044 - Longest Duplicate Substring（最長重複子字串）

題目。 找出在 s 中至少出現兩次的最長子字串；兩次出現可以重疊。回傳其中任何一個， 若沒有任何子字串重複就回傳空字串。

輸入／輸出。 輸入一個字串，輸出一個字串。

範例。 s = "banana" → "ana"（出現在索引 1 與 3，而且是重疊的）；s = "abcd" → ""。

限制。 2 <= len(s) <= 3 * 10^4，小寫英文字母。「有沒有長度 L 的重複子字串」對 L 是單調 的，所以標準解法是對 L 二分搜尋、每次用 Rabin-Karp rolling hash 回答；或者完全不用隨機性， 直接從 suffix array 加上它的 LCP 陣列把答案讀出來。
