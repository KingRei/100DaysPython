100 Days of Python - day 40

把一個數字集合存成一個 Python 整數的各個位元，「這兩個集合有幾個共同成員？」就會比問兩個 set 物件快大約六十倍，記憶體只剩三十一分之一。再用 int.bit_count() 數這個整數裡有幾個 1，它會把 C 世界流傳下來的各種聰明 popcount 公式全部甩開，快四到三十五倍。

這是今天好的那一半。另一半是：從 C 或 Java 抄過來的位元技巧，碰上 Python 整數會怎樣。bin(-5).count('1') 回傳 2，C 說是 31。「不用 + 做加法」的教科書解法，遇到 -1 + 1 永遠不會結束。LeetCode 137 的一個標準解法兩個範例都過，然後在每一筆答案是負數的測資上答錯。這些全部不會報錯。

昨天用 bitmask 解 N-Queens 時，靠 free & -free 挑下一欄，沒解釋為什麼行得通。今天就來講為什麼，以及 Python 整數的哪一個性質決定了哪些位元技巧可以信。

Python 的整數沒有寬度

在 C 裡，int 是 32 bits。-5 存成 32 個 bit：前面一串 1，最底下是 011。Python 的 int 沒有「32」這件事。它表現得像是有無限多個 bit，所以 -5 是從第 3 位開始往上每一位都是 1，一直到無窮遠。

這一個事實把所有位元技巧分成兩群。

一欄一欄各自算的技巧是安全的。&、|、^、~ 算答案的第 k 位時，只看輸入的第 k 位，其他都不管。所以不論寬度多少答案都一樣，拿來處理負的 Python 整數，跟在 C 裡完全相同。

會問「總共幾個 bit？」的技巧需要一個寬度，而 Python 從來不記寬度。負數的 popcount、「最高位是哪一位」、還有任何等著進位從第 31 位掉出去的迴圈，都屬於這一群。在 Python 整數上，根本沒有第 31 位可以掉出去。

兩個小函式把寬度裝回去，今天每一個陷阱都靠它們修：

M32 = (1 << 32) - 1

def u32(x):           # keep the low 32 bits - what a C uint32_t would hold
    return x & M32

def s32(u):           # read 32 bits as signed: bit 31 is worth -2**31, not +2**31
    u &= M32
    return u - (1 << 32) if u >> 31 else u

u32(-5) 是 4,294,967,291，s32 再把它讀回 -5。

工具箱：以 x = 180 為例

測試、設定、清除、翻轉第 k 位，都是一次位移加一個運算子：x >> k & 1、x | 1 << k、x & ~(1 << k)、x ^ 1 << k。真正值得背起來的是三個處理「最低位」的：

它們都來自同一件事：減 1 會把最低的那個 1 變成 0，把它底下所有的 0 變成 1，上面的完全不動。所以 x & (x - 1) 剛好抹掉最低的 1：180 變 176。-x 等於 ~x + 1，會把最低那個 1 以上的每一位翻轉、那個 1 本身不動，所以 x & -x 只留下那一位：4。x | (x + 1) 則是把最低的 0 打開：181。

x & -x 就是 Fenwick tree 在各段區間之間跳躍的那一步（Day 29），也是昨天 N-Queens 從 mask 裡拿出一個空欄的方法。(x & -x).bit_length() - 1 是尾端 0 的個數，180 是 2。

往下之前先講一個運算子優先順序的陷阱。算術運算綁得比位移緊，所以 1 << n - 1 的意思是 1 << (n - 1)。n = 4 時得到 8（1000），不是你要的四個 1（15）。要寫 (1 << n) - 1。反過來 C 那個經典陷阱 x & 1 == 0 在 Python 不存在，因為這裡 & 綁得比 == 緊。

popcount 的五種寫法

數一個數字裡有幾個 1（popcount）有一整套民間流傳的寫法：

def popcount_shift(x):          # one round per bit, up to the top 1
    count = 0
    while x:
        count += x & 1
        x >>= 1
    return count

def popcount_kernighan(x):      # one round per 1
    count = 0
    while x:
        x &= x - 1              # drop the lowest 1
        count += 1
    return count

位移迴圈每一位都看一次。Kernighan 的迴圈用 x & (x - 1) 從一個 1 直接跳到下一個 1，所以有幾個 1 就跑幾圈：

在 200,000 個隨機 32-bit 數字上，Kernighan 跑 3,199,046 圈，位移迴圈跑 6,200,129 圈，剛好一半：隨機的 32-bit 數字平均有 16 個 1，但到最高位的 1 為止平均有 31 位。

傳統寫法裡最聰明的一個完全不用迴圈，一次把 32 位加起來，叫做 SWAR（「在一個暫存器裡做 SIMD」）：

def popcount_swar32(x):
    x = x - ((x >> 1) & 0x55555555)                   # 16 two-bit counts
    x = (x & 0x33333333) + ((x >> 2) & 0x33333333)    # 8 four-bit counts
    x = (x + (x >> 4)) & 0x0F0F0F0F                   # 4 byte counts
    return ((x * 0x01010101) & 0xFFFFFFFF) >> 24      # add the 4 bytes

第一行把每兩個 bit 換成「這兩位裡有幾個 1」。第二行把相鄰兩組加成 4-bit 的計數，第三行再加成每個 byte 一個計數，最後那個乘法把四個 byte 加總到最高的 byte。在 C 裡這是最快的。在 Python 裡：

內建的 int.bit_count()（Python 3.10 以後）比 SWAR 快五倍。Python 的每一個 &、>>、+ 都要單獨經過一次直譯器，所以最快的寫法是 Python 層級運算最少的那個，而 bit_count() 把整個迴圈放在 C 裡跑完。它也能處理任意大小的整數：一個一百萬位的整數，它大約 70 微秒，bin(x).count('1') 則要大約 6 毫秒，因為它得先組出一個一百萬字元的字串。

無聲的錯誤：負數的 popcount

現在拿 -5 問它們。C 的 __builtin_popcount 和 Java 的 Integer.bitCount 都說 31。Python 說：

bin(-5).count('1')     -> 2          bin(-5) is '-0b101': it counts the digits of 5
(-5).bit_count()       -> 2          documented as the popcount of abs(x)
Kernighan / shift loop -> never returns
(-5 & M32).bit_count() -> 31

Kernighan 不會結束，因為負數做 x & (x - 1) 之後還是負數。數值一路是 -5、-6、-8、-16、-32……跑了 40 圈之後 x 大約是負兩兆兩千億，上面永遠還有下一個 1。修法就是數之前先把寬度釘住。

LeetCode 338 - Counting Bits（比特位計數）

題目。從 0 到 n 的每一個整數，回報它的二進位表示裡有幾個 1。

輸入／輸出。一個整數 n；回傳長度 n + 1 的 list，第 i 個元素是 i 的 1 的個數。

範例。n = 5 得到 [0, 1, 1, 2, 1, 2]：0 是 0、1 是 1、2 是 10、3 是 11、4 是 100、5 是 101。

限制。0 <= n <= 100,000。每個數字各自呼叫 popcount 其實已經夠快；進階要求是只掃一遍、不准用內建 popcount，這才讓它變成一題 DP。

leetcode.com/problems/counting-bits

class Solution:
    def countBits(self, n: int) -> list[int]:
        ans = [0] * (n + 1)
        for i in range(1, n + 1):
            ans[i] = ans[i >> 1] + (i & 1)   # i without its last bit, plus that bit
        return ans

i >> 1 把最後一位丟掉，得到一個比較小、表格裡早就填好的數字；i & 1 是被丟掉的那一位。同一張表也可以從最低位技巧推出來：ans[i] = ans[i & (i - 1)] + 1，因為 i 剛好比「拿掉最低那個 1 的 i」多一個 1。

一個 Python 整數當作一百萬個成員的集合

第 v 位是 1 就代表「v 在集合裡」。交集是 &、聯集是 |、大小是 bit_count()，每一個都是 C 裡對機器字組跑一次迴圈。從 0 到 999,999 隨機抽兩組各 100,000 個成員，共同成員有 9,955 個。問兩個 set 物件大約 5 ms，(a & b).bit_count() 大約 0.08 ms。set 佔 4,194,520 bytes，整數佔 133,360。

這跟 Day 34 subset sum 的 bits |= bits << x（一次更新 DP 表的一整列）、Day 32 的 Bloom filter、Day 27 的 Jaccard 相似度是同一招。

有一個變慢的問題，小測資裡永遠看不到。x |= 1 << v 看起來像是「加一個成員」的常數時間操作，但 Python 整數不能原地修改，每一次 |= 都會做出一個跟整個集合一樣長的新整數。這樣往一百萬位的集合加 20,000 個成員，大約要 220 ms。先填一個 bytearray 再一次轉換，大約 3 ms：

def to_bitset(values, universe):
    buf = bytearray((universe + 7) // 8)
    for v in values:
        buf[v >> 3] |= 1 << (v & 7)       # byte v // 8, bit v % 8
    return int.from_bytes(buf, 'little')

LeetCode 136 - Single Number（只出現一次的數字）

題目。一個 list 裡，除了一個值之外，每個值都剛好出現兩次，找出只出現一次的那個。

輸入／輸出。一個非空的整數 list nums；回傳落單的那個值。

範例。[4, 1, 2, 1, 2] 得到 4：兩個 1 配成一對、兩個 2 配成一對，剩下 4。

限制。最多 30,000 個值，介於 -30,000 到 30,000，要求線性時間「而且」常數額外空間。空間限制就是不准用 Counter 或 set、逼你用位元技巧的那一條。

LeetCode 137 - Single Number II（只出現一次的數字 II）

題目。同上，只是其他每個值都剛好出現三次。

輸入／輸出。一個非空的整數 list nums；回傳只出現一次的那個值。

範例。[0, 1, 0, 1, 0, 1, 99] 得到 99，0 和 1 各出現三次。

限制。最多 30,000 個值，範圍是整個 signed 32-bit，一樣要線性時間、常數額外空間。有號範圍就是陷阱所在：答案可以是負數，而在 Python 裡，這決定了逐欄計數的解法對不對。

leetcode.com/problems/single-number-ii

class Solution136:
    def singleNumber(self, nums):
        return reduce(xor, nums, 0)       # every pair cancels, column by column

class Solution137:
    def singleNumber(self, nums):
        ones = twos = 0                   # per column: seen once / seen twice
        for x in nums:
            ones = (ones ^ x) & ~twos
            twos = (twos ^ x) & ~ones
        return ones

XOR 能抵銷成對的，所以 136 一行解決。它抵銷不了三個一組的，所以 137 在每一欄維持一個 0、1、2、0 循環的計數器，存在 ones 和 twos 兩個整數裡。兩個解都只用 ^、&、~，所以完全不需要寬度就能處理負數：[-7, 3, 3] 得到 -7。

137 另一個有名的解法，是對 32 欄的每一欄數「有幾個數字這一位是 1」，保留次數不是 3 的倍數的那些欄。少了最後那個 s32，就會變成這樣：

nums                      ones/twos   count + s32   count, no s32
[2, 2, 3, 2]                      3             3               3
[0, 1, 0, 1, 0, 1, 99]           99            99              99
[-2, -2, -3, -2]                 -3            -3   4,294,967,293

重建出來的數字第 31 位是 1。沒有 s32 的話，Python 會把那一位算成正二十一億而不是負二十一億，-3 就變成 4,294,967,293。兩個範例都過。在整個範圍上隨機測 1,000 筆，它錯了 502 筆，剛好就是答案為負數的那些。

LeetCode 371 - Sum of Two Integers（兩整數之和）

題目。不用 + 或 - 運算子，把兩個整數加起來。

輸入／輸出。兩個整數 a 和 b；回傳它們的和。

範例。a = 2, b = 3 得到 5。2 ^ 3 = 1 是不管進位的和，(2 & 3) << 1 = 4 是進位，1 ^ 4 = 5 之後就沒有進位了。

限制。-1000 <= a, b <= 1000。範圍很小，但允許負數，而在 Python 裡問題全出在這裡。

leetcode.com/problems/sum-of-two-integers

把 C 的解法原封不動打進 Python：

while b:
    a, b = a ^ b, (a & b) << 1
return a

兩個範例都過。然後試 -1 + 1。這一對數字會變成 (-2, 2)、(-4, 4)、(-8, 8)……進位每一圈往左移一格。在 C 裡，它移到第 31 位之後就被擠出 32-bit 字組，32 圈後消失。在 Python 裡它無處可去：跑 40 圈之後進位是 1,099,511,627,776，還在長，迴圈永遠不會停。

每一圈把兩個值都 mask 到 32 bits，進位就會掉出去，-1 + 1 在 32 圈後停在 0。但只有 mask 的話，-1 + -1 會得到 4,294,967,294，因為答案是以無號 32-bit 的形式回來的。最後一行把第 31 位當成正負號讀回來：

class Solution:
    def getSum(self, a: int, b: int) -> int:
        a, b = a & M32, b & M32
        while b:
            a, b = (a ^ b) & M32, ((a & b) << 1) & M32   # carry falls off bit 31
        return a if a < 1 << 31 else a - (1 << 32)       # bit 31 is the sign

這就是 371 在 Python 面試時要講的重點：演算法本身三行，難處全在把 C 免費給你的寬度自己補回去。

複雜度

operation                                   time               space
test / set / clear / lowbit (fixed width)   O(1)               O(1)
popcount, shift loop                        O(bit length)      O(1)
popcount, Kernighan                         O(number of 1s)    O(1)
int.bit_count() on an n-bit int             O(n / 64)          O(1)
Counting Bits (LeetCode 338)                O(n)               O(n)
bitset &, |, bit_count over a universe U    O(U / 64)          O(U / 8) bytes
bitset built by x |= 1 << v, m members      O(m * U / 64)      O(U / 8) bytes
Single Number I / II (136 / 137)            O(n)               O(1)
Sum of Two Integers (371), 32-bit           32 rounds at most  O(1)

第一列的每個 O(1) 都假設寬度固定。在一個一百萬位的 Python 整數上，這些操作每一個都要花跟長度成正比的時間，這也是為什麼一位一位建 bitset 會變成平方時間。

之後會在哪裡用到

凡是大集合需要快速取交集的地方，bitset 都會回來：一張圖若每個節點存成一個整數，「共同鄰居」就是一次 &；HyperLogLog 靠雜湊值前面有幾個 0 來估計看過多少不同的東西，在 Python 裡那就是 bit_length()。AI 那一側，int4 量化把兩個 4-bit 權重塞進一個 byte，讀回來全靠位移和 mask，而且一樣要回答「第 3 位是不是正負號」這個問題。雜湊函式和亂數產生器也是用 XOR 和位移組出來的，而且一律在固定寬度下運作，所以移植到 Python 時每一步後面都要補 & M32 或 & M64。

這個習慣到哪都用得上：從別的語言搬過來的位元技巧在 Python 給出奇怪的數字時，先檢查它是不是問了「總共幾個 bit」。
