100 Days of Python - day 44

把一百萬個浮點數的平方加起來，在我的機器上用 Python for 迴圈要 41 毫秒，用 np.dot 只要 0.1 毫秒——快了大約三百倍，答案到印出來的最後一位都一樣。今天後半段，一個手寫 autograd 算出的梯度花了約 16 毫秒；同一個梯度寫成一條矩陣公式，只要約 0.005 毫秒（都是在我機器上的單次量測）。兩半其實是同一課：把迴圈從 Python 直譯器裡搬出來，變成一次處理整個陣列的呼叫。

這是系列進入機器學習段落的第一天，而前幾天「無聲的失敗」這條主線直接延續下來。下面這些都不會丟出任何錯誤：

  • 形狀 (5, 1) 的預測值對上形狀 (5,) 的目標值，均方誤差算出 4.01 而不是 0.01，因為 NumPy 默默建了一張「每個預測對每個目標」的 5 × 5 表格。
  • 把兩張 uint8 圖片逐像素平均，200 和 100 變成 22，而不是 150。
  • v[[0, 2]][0] = 99 什麼都沒改到。
  • 把 grad += g 寫成 grad = g 的 autograd，會說 x * x 在 3 的導數是 3，不是 6。
  • 不照拓樸順序走圖的 autograd，會說 (2x)² 在 3 的導數是 48，不是 24。
  • 忘記把梯度歸零的訓練迴圈，最後 loss 停在 3.09，而不是 0.0083。

昨天（Day 43）講的是把工作拆給多個 thread 和 process。向量化是另一種平行：一次呼叫、一個 C 裡的緊湊迴圈，常常還用上一次處理好幾個數字的 SIMD 指令——而且 NumPy 在跑數值迴圈時會放掉 GIL。

為什麼迴圈慢、陣列快

Python 的浮點數 list 其實是一串指標。每個指標指向一個獨立的 float 物件，各自帶著型別標記和參考計數；s += x * x 讓直譯器查 x 的型別、找到它的乘法、為結果建立一個新的 float 物件，加法再來一次——重複一百萬次。NumPy 陣列則是一整塊原始的 8 位元組 double，所有元素共用一個型別，所以 np.dot(a, a) 就是一次呼叫，在 C 裡對連續記憶體跑一個迴圈。

for loop              41.4 ms
sum(generator)        61.9 ms
(a * a).sum()          1.2 ms      36x faster than the loop
np.dot(a, a)           0.1 ms     284x

（一次量測；確切倍數會飄，數量級不會。）(a * a).sum() 比 np.dot 慢，是因為它先寫出一整個裝了一百萬個平方的新陣列，再把它讀回來加總；np.dot 一趟就把乘和加做完。

shape 與 strides：陣列到底是什麼

一個陣列 = 一塊緩衝區 + 一個 shape + strides：沿著每個軸走一步要跳幾個位元組。np.arange(12).reshape(3, 4) 是十二個整數，shape (3, 4)、strides (32, 8)——往下一列跳 4 × 8 位元組，往右一欄跳 8 位元組。

m                {'shape': (3, 4), 'strides': (32, 8), 'shares memory': True, 'C-contiguous': True}
m.T              {'shape': (4, 3), 'strides': (8, 32), 'shares memory': True, 'C-contiguous': False}
m[:, ::2]        {'shape': (3, 2), 'strides': (32, 16), 'shares memory': True, 'C-contiguous': False}
m.T.reshape(12)  {'shape': (12,), 'strides': (8,), 'shares memory': False, 'C-contiguous': True}

轉置就是把 strides 對調；每隔一欄取一個就是把其中一個 stride 加倍。沒有任何數字被搬動，所以兩者都不花成本，也都是 view：寫進去就是寫進 m。最後一行是例外：一列一列讀 m.T，在緩衝區裡跳的方式沒辦法用單一組 strides 描述，所以 reshape 只好複製一份。

第一個無聲的失敗就在這裡。s = v[::2]; s[:] = 0 會把 v 每隔一個元素歸零，因為 slice 是 view。但用 list 當索引的 v[[0, 2]] 一定會複製，所以 v[[0, 2]][0] = 99 是把 99 寫進一份臨時副本然後丟掉——v 沒變，也沒有人抱怨。（單一指派 v[[0, 2]] = 99 才會真的寫進 v。）

LeetCode 566 - Reshape the Matrix（重塑矩陣）

題目。 給一個矩陣和新的列數、欄數，把裡面的數字重新排成新的形狀：從舊矩陣一列一列讀出來，再一列一列填進新矩陣。如果新形狀裝不下剛好同樣多的數字，就原封不動回傳舊矩陣。

輸入／輸出。 mat 是 m × n 的二維 list，另外給兩個整數 r、c。回傳 r × c 的二維 list；當 m * n != r * c 時回傳 mat 本身。

範例。 mat = [[1, 2], [3, 4]]、r = 1, c = 4：依序讀出 1、2、3、4，寫成一列 [[1, 2, 3, 4]]。如果 r = 2, c = 4，會有 8 個位置卻只有 4 個數字，所以答案是原本的 [[1, 2], [3, 4]]。

限制。 m、n 介於 1 到 100，數值介於 -1000 到 1000，r、c 介於 1 到 300。規模小到任何線性解都會過；唯一要做對的是順序和大小檢查。

依讀取順序第 k 個元素，在舊矩陣的第 k // n 列、第 k % n 欄，在新矩陣的第 k // c 列、第 k % c 欄——這正是 strides 在做的算術：

class Solution:
    def matrixReshape(self, mat: list[list[int]], r: int, c: int) -> list[list[int]]:
        m, n = len(mat), len(mat[0])
        if m * n != r * c:
            return mat
        out = [[0] * c for _ in range(r)]
        for k in range(m * n):
            out[k // c][k % c] = mat[k // n][k % n]
        return out

在 NumPy 裡就是 np.array(mat).reshape(r, c)，輸入是連續記憶體時它只是一個 view。陷阱是順序：reshape(3, 2, order='F') 是一欄一欄讀，會把 [[1, 2, 3], [4, 5, 6]] 變成 [[1, 5], [4, 3], [2, 6]]，而不是 [[1, 2], [3, 4], [5, 6]]——看起來是個正常的矩陣，只是錯的那一個。

Broadcasting，以及它藏起來的 bug

broadcasting 讓不同形狀的陣列可以放在同一個運算裡。規則是：把兩個 shape 靠右對齊；每一對大小要嘛相等、要嘛其中一個是 1，而 1 會被拉伸成另一邊的大小。

def broadcast_shape(s1, s2):
    out = []
    for i in range(1, max(len(s1), len(s2)) + 1):
        a = s1[-i] if i <= len(s1) else 1
        b = s2[-i] if i <= len(s2) else 1
        if a != b and 1 not in (a, b):
            raise ValueError(f'shapes {s1} and {s2} do not broadcast')
        out.append(max(a, b))
    return tuple(reversed(out))

(200, 5) 配 (5,) 得到 (200, 5)：每一列都加上同一個 bias。(3,) 配 (3, 1) 得到 (3, 3)——bug 就住在這第二種。很多模型輸出的預測是一欄，shape (n, 1)，目標值卻是攤平的 (n,)：

y (5,), pred (5, 1): pred - y has shape (5, 5)
MSE with pred.ravel(): 0.0100   MSE with pred as (5, 1): 4.0100  (no error, no warning)

每個預測都和每個目標比了一次，.mean() 開開心心把 25 格全部平均。用這個 loss 去訓練，會把每個預測都推向所有目標的平均值。修法是一個 .ravel()（或 reshape(-1)），習慣則是每個 loss 之前都 assert pred.shape == y.shape。

這一節另一個無聲的失敗是整數溢位繞回。uint8 只裝得下 0 到 255，而 NumPy 不會自動幫你加寬：200 + 100 是 44，所以用 (a + b) // 2 平均兩張圖片會得到 22，而不是 150。先轉型：(a.astype(np.int16) + b) // 2 得到 [150, 100, 130]。

把雙層迴圈向量化：兩兩距離

300 個三維點兩兩之間的距離，用 Python 迴圈算花了約 205 毫秒（一次量測，這一節的計時都是）。broadcasting 用一行 x[:, None, :] - x[None, :, :] 寫出同樣的東西，約 4.7 毫秒。但它會建出一個 (n, n, 3) 的陣列，裝著每一對的差：300 個點是 2.2 MB，20,000 個點是 9,600 MB。向量化是用記憶體換時間。

恆等式 |a - b|² = |a|² + |b|² - 2 a·b 可以避開那個大陣列：一個矩陣乘法 x @ x.T 加兩個向量，約 0.63 毫秒。它也有自己的陷阱。一個點到自己的距離應該是 0，但 |a|² + |a|² - 2 a·a 是用浮點數算的，可能算出一點點負數——這次最小到 -8.9e-16。在 500 個隨機點上，有 63 個距離平方小於零，np.sqrt 把這 63 個全變成 NaN，只留下一個 runtime warning。開根號前先夾到 0——所有正式的實作都這樣做。

導數的三種算法

訓練模型就是沿著 loss 的斜率往下走，所以我們需要導數。第一種方法不需要任何理論：把輸入推一點點，看輸出變多少。

def central_diff(f, x, h):
    return (f(x + h) - f(x - h)) / (2 * h)

對 sin 在 1 這一點，導數是 cos 1：

h = 1e-2   forward 4.2e-03   central 9.0e-06
h = 1e-5   forward 4.2e-06   central 1.1e-11
h = 1e-8   forward 3.0e-09   central 2.6e-09
h = 1e-12  forward 4.3e-05   central 1.2e-05

h 變小一開始會變準，到大約 1e-5 之後反而變差：f(x+h) 和 f(x-h) 幾乎每一位都一樣，相減之後剩下的大多是捨入誤差。差分很適合拿來*檢查*梯度，但拿來訓練一個有一百萬個權重的模型完全不行，因為每個權重都要把整個函式算兩次。

第二種方法是 forward mode：把導數跟著數值一起帶著走。dual number 是一對 (值, 導數)，乘法裡內建了乘積法則：

class Dual:
    def __init__(self, val, der=0.0):
        self.val, self.der = val, der

    def __mul__(self, o):
        o = o if isinstance(o, Dual) else Dual(o)
        return Dual(self.val * o.val, self.der * o.val + self.val * o.der)

f(x) = x sin x + 3x 在 2 得到 f' = 3.077003753731，每一位都精確。但一趟只能得到對*一個*輸入的導數。一個有 200 個輸入的函式，就要跑 200 趟。

第三種方法 reverse mode 是 PyTorch 和 JAX 訓練時用的：一趟 forward 把計算過程記下來，一趟 backward 一次得到對*所有*輸入的導數。同樣那個 200 個輸入的函式：1 趟 forward 加 1 趟 backward，數字完全相同。

一個迷你 autograd

每個 Value 都記得自己是由哪些值算出來的，並帶著一個小函式，負責依照局部規則把梯度送回去——對 out = a * b，送到 a 的梯度是 b * out.grad：

def __mul__(self, o):
    o = self._wrap(o)
    out = Value(self.data * o.data, (self, o), '*')

    def _backward():
        self.grad += o.data * out.grad
        o.grad += self.data * out.grad
    out._backward = _backward
    return out

backward() 先把圖排成拓樸順序——就是 Day 13 的演算法，這裡寫成迭代式的 DFS——再從輸出往輸入，依序呼叫每個 _backward：

def backward(self):
    order = self.topo()            # every node after all of its inputs
    for v in order:
        v.grad = 0.0
    self.grad = 1.0
    for v in reversed(order):      # every node after all of its users
        v._backward()
    return order

L = (a*b + c) * f，a=2, b=-3, c=10, f=-2：L = -8，梯度是 dL/da = 6、dL/db = -4、dL/dc = -2、dL/df = 4。拿一個更複雜的函式 tanh(p*q + r) * p + exp(q/r) - p² 跟 central difference 做梯度檢查，相對誤差 1.3e-10。

這段程式碼裡有兩行決定了正確性，而任何一行寫錯都還是會回傳一個數字：

是 +=，不是 =。 在 x * x 裡，兩個輸入是同一個節點，所以 _backward 會送兩份 3 給 x。累加得到 6，是 x² 正確的導數。直接指派只留下第二次寫入：3。

拓樸順序。 最直覺的 backward 寫法是「先跑自己的 _backward，再對每個輸入遞迴」。對 q = 2x; y = q * q，遞迴會走到 q 兩次，每次都把 q 完整的梯度再推給 x 一次：得到 48 而不是 24，而且走了 7 次節點，拓樸順序只要 4 次。「每個節點都要等它所有的使用者回報完才往下傳」，正是拓樸順序保證的事。

第三個 bug 不在 autograd 裡，在訓練迴圈裡。梯度天生就會累加，所以每一步之間必須歸零。用 20 個點擬合 y = 3x - 0.5，跑 60 步：

zeroing gradients:     w = 3.020, b = -0.534, final loss 0.0083
never zeroing them:    w = 6.089, b = -1.029, final loss 3.0924

沒有歸零時，每一步用的是之前所有梯度的總和，權重衝過頭，loss 每十步看一次是 4.40、2.18、2.59、0.015、2.78、2.40，一直彈跳而不是收斂。這就是 PyTorch 的訓練迴圈每一輪都要呼叫 optimizer.zero_grad() 的原因。

回到向量化：把梯度寫成一條公式

純量的 autograd 是對的，但很慢。一個線性模型在 200 列、5 個特徵上的均方誤差，是一張 4,408 個節點的 Value 圖，算梯度一次量測約 16 毫秒。用整個陣列手算同一個導數得到 2/n · Xᵀ(Xw - y)：約 0.005 毫秒，兩個梯度相差 5.3e-15。真正的 autograd 函式庫就是這樣做的：它們的節點是整個陣列，每個節點的 backward 規則都是一條向量化的公式，所以圖上只有少少幾個節點，而不是幾千個。

LeetCode 150 - Evaluate Reverse Polish Notation（逆波蘭表示法求值）

題目。 計算一個用逆波蘭表示法（Reverse Polish Notation）寫的算式：每個運算子都寫在它的兩個運算元後面，所以不需要括號。

輸入／輸出。 tokens 是一個字串 list，每個元素是整數，或 +、-、*、/ 其中之一。回傳算式的整數值。兩個整數相除只留整數部分，往零的方向捨去。

範例。 ["2", "1", "+", "3", "*"] 代表 (2 + 1) * 3 = 9：推入 2、推入 1，+ 把兩個彈出、推入 3，再推入 3，* 把兩個彈出、推入 9。["4", "13", "5", "/", "+"] 是 4 + 13 / 5 = 4 + 2 = 6。

限制。 最多一萬個 token；每個數字介於 -200 到 200；算式一定合法、不會除以零，所有中間結果都放得進 32 位元整數。會咬人的限制是負數商的「往零捨去」。

Day 02 的 stack 包辦了一切：

class Solution:
    def evalRPN(self, tokens: list[str]) -> int:
        st = []
        for t in tokens:
            if t in ('+', '-', '*', '/'):
                b, a = st.pop(), st.pop()
                if t == '+':
                    st.append(a + b)
                elif t == '-':
                    st.append(a - b)
                elif t == '*':
                    st.append(a * b)
                else:
                    st.append(int(a / b))      # truncate, NOT a // b (which floors)
            else:
                st.append(int(t))
        return st[0]

陷阱是 Python 的 // 是*往下*取整：6 // -132 是 -1，往零捨去則是 0。只有正數的範例怎麼寫都會過。LeetCode 那個比較長的範例 10 6 9 3 + -11 * / * 17 + 5 +，用 int(a / b) 得到 22，用 // 得到 12。

把同一台 stack 機器裡的整數換成 Value 物件，求值的過程就會*建出計算圖*。x y * x + y / 在 x = 2, y = -3 得到 1.3333，再呼叫一次 backward()，得到 d/dx = 0.6667、d/dy = -0.2222——剛好就是 (y + 1)/y 和 -x/y²。autograd 的 tape 就只是這樣：一邊求值一邊記下運算，然後倒著重播。

這些之後會用在哪

這個系列的機器學習段落，全都建立在今天這兩個概念上。梯度下降和它的變形（momentum、Adam）就是一個呼叫 backward()、再更新權重的迴圈——前提是先把梯度歸零。線性迴歸和邏輯迴歸，就是今天的 2/n Xᵀ(Xw - y) 換個 loss。多層神經網路的反向傳播，就是在一張節點都是矩陣乘法的圖上跑 reverse mode，今天的三個 bug 在那裡一個不少，每個 loss 函式裡還多一個 broadcasting 的。PyTorch 的 autograd 是一條照拓樸順序倒著重播的運算 tape；JAX 把同一個想法寫成函式轉換。而 broadcasting 的規則，就是 GPU 把同一個 bias 加到整個 batch 的 activation 上時用的那一條。

值得留下的習慣：每個 loss 之前先 assert shape；每個手寫的梯度都至少用 central difference 檢查一次；當一個對數字跑的 Python 迴圈很慢時，去找能說出同一件事的陣列運算式。
