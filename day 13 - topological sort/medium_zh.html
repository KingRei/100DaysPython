100 Days of Python — day 13

你等過的每一次相依性解析——npm install、CI pipeline、試算表重新計算、大學時被擋修的課表 ——說穿了都是一張圖加一個演算法。那個演算法叫拓樸排序（topological sort），二十行寫得完。

昨天我們學會走訪一張圖，今天要用「尊重相依關係」的順序走它。你會發現這其實就是昨天的 BFS 和 DFS，只多記了一點東西。接下來整個圖論章節都是這個套路。

我們到底在要什麼

一張有向圖的拓樸順序，是把所有頂點排成一列，使得每一條邊 u -> v 都滿足 u 排在 v 前面。 邊要讀成「u 必須先發生」。

接下來這件事值得講清楚：這種排序存在若且唯若圖上沒有環。如果 A 依賴 B、B 依賴 C、 C 又依賴 A，那不管怎麼排都不可能讓三個都「排最前面」。所以 DAG（directed acyclic graph， 有向無環圖）剛好就是「可以被排程」的那一類圖，而下面兩個演算法都是順手就把環偵測出來， 不需要多跑一趟。

另外要注意：一張 DAG 通常有很多組合法的順序，我們這張圖就有好幾百組。兩個演算法只是 剛好吐出不同的那一組而已。

Kahn's algorithm：把沒被擋住的先剝掉

一個頂點的 in-degree 是指向它的邊數，也就是還有幾件事卡著它。in-degree 為 0 的點， 現在就可以做。

所以做法是：先把所有自由的點收集起來，取一個出來輸出，然後告訴它的後繼者「你少了一個 阻礙」。任何降到 0 的後繼者也就自由了。

from collections import defaultdict, deque

def build(n, edges):
    adj = defaultdict(list)
    indeg = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1
    return adj, indeg

def kahn(n, edges):
    adj, indeg = build(n, edges)
    queue = deque(v for v in range(n) if indeg[v] == 0)
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1          # u is placed, so v has one fewer blocker
            if indeg[v] == 0:      # v is now free to go
                queue.append(v)
    return order if len(order) == n else None

最後那一行就是全部的環偵測。在環上的點永遠不會降到 in-degree 0，因為要幫它減一的那個點， 自己也還卡在環後面等。於是 queue 提早空掉、輸出的長度不足 n。len(order) == n 就是判斷式， 不需要任何額外機制。

我實際上比較常用的版本

每一輪不要只取一個點，而是把整個 frontier 一次取光，輸出就會自然分層：

round 0: ['intro programming', 'discrete math']
round 1: ['data structures', 'algorithms', 'linear algebra']
round 2: ['databases', 'machine learning']
round 3: ['capstone']

同一輪裡的東西彼此互不相依，也就是說它們可以同時跑。build 系統在決定怎麼用你的 CPU 核心時，算的就是這個；而輪數等於圖上最長路徑的長度，也就是不管你開幾條執行緒都壓不下去的 最短排程。八門課、四學期，再有熱情也變不成三學期。

還有一個變形值得記，因為面試官很愛問：把 queue 換成 heapq，得到的就是字典序最小的拓樸 順序，複雜度 O(V log V + E)。Day 05 的 heap 又出來打工了。

DFS post-order：先完成，再倒過來

另一條路直接沿用昨天的 DFS。能多深就走多深；當一個點已經沒有還沒探索的出邊時，代表從它 出發能到的東西全都處理完了，所以此刻把它接到串列尾端，就保證它排在所有後繼者之後。 最後把完成順序反轉，就是一組拓樸順序。

WHITE, GREY, BLACK = 0, 1, 2      # unseen / on the current path / finished

def dfs_topo(n, edges):
    adj, _ = build(n, edges)
    color = [WHITE] * n
    finished = []

    def visit(u):
        color[u] = GREY
        for v in adj[u]:
            if color[v] == GREY:                    # back edge -> cycle
                return False
            if color[v] == WHITE and not visit(v):
                return False
        color[u] = BLACK
        finished.append(u)                          # successors already out
        return True

    for s in range(n):
        if color[s] == WHITE and not visit(s):
            return None
    return finished[::-1]

三種顏色是大家最常寫錯的地方。昨天只要一個 visited 集合就夠，因為我們只在乎「有沒有去過」。 這裡我們必須知道某個點是不是在目前這條路徑上——那就是灰色——因為走進灰色的點代表繞回 自己身上了。走進黑色的點則完全沒問題，那只是兩條分支共用了同一個後代而已。

只要圖有點深度，就改用迭代版：CPython 大約 1000 層就投降，而一條 1000 個檔案的相依鏈一點 都不稀奇。訣竅是每個 stack frame 存一個迭代器，這樣才能從上次的位置接著走，而不是重掃 一次鄰居清單。

失敗的時候，要說清楚為什麼

回傳 None 很誠實，但沒有用。build 工具應該要把環印出來。DFS 時順手維護一個 parent 陣列，當你從 u 撞到灰色的 v，就沿著 parent 從 u 一路走回 v：

kahn      : None
dfs       : None
the cycle : 0 -> 2 -> 5 -> 7 -> 0
as courses: intro programming -> data structures -> databases -> capstone -> intro programming

這就是「偵測到循環相依」和「使用者看得懂、修得動的訊息」之間的差別。

複雜度

兩個演算法都是每個點碰一次、每條邊碰一次：時間 O(V + E)、空間 O(V)。Kahn 需要 in-degree 陣列，DFS 需要顏色陣列加一個堆疊；heap 版本多一個 log。這裡沒有什麼漂亮的漸進 優化可以做——真正要選的是「你還想順便拿到什麼」。

Kahn 給你分層，以及一個幾乎免費的環檢測；DFS 給你環本身，而且能跟其他建立在 DFS 樹上的演算法接起來。我排程時用 Kahn，本來就在走圖時就用 DFS。

LeetCode 207 — Course Schedule

numCourses 門課，prerequisites[i] = [a, b] 代表要先修 b 才能修 a。問你修不修得完。

def can_finish(num_courses, prerequisites):
    edges = [(b, a) for a, b in prerequisites]      # take b before a
    return kahn(num_courses, edges) is not None

題目問的就只是「這張圖是不是 DAG」。面試時值得講出來的一個坑：邊的方向要檢查。 [a, b] 從左讀到右是「a 需要 b」，所以邊是 b -> a；方向寫反的版本在對稱的測資上會過， 在真實測資上會掛。LeetCode 210 是同一個函式，只是回傳順序而不是布林值。

還有哪些地方會用到

任何需要「照合法順序執行一堆步驟」的東西，底層都是拓樸排序。build 系統和套件管理員是最 明顯的例子，但它其實也藏在 autograd 裡：backward pass 就是計算圖的反向拓樸走訪，這也是 為什麼你不用指定順序，框架就能把梯度算出來。編譯器的指令排程與死碼消除同樣靠它；而任何 會把互不相依的工作平行派發的 task runner，算的其實就是 kahn_levels。
