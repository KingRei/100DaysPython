Interval DP and tree DP: choosing the split point instead of the next item

Code: day 36 on GitHub

100 Days of Python - day 36

Here is a function that returns a wrong answer without raising anything, and the bug is not in the recurrence. It is in the order of two for loops.

for i in range(n):
    for j in range(i + 1, n):
        for k in range(i, j):
            cost = dp[i][k] + dp[k + 1][j] + dims[i] * dims[k + 1] * dims[j + 1]
            dp[i][j] = min(dp[i][j], cost)

That is matrix chain multiplication, written the way everyone writes a double loop over a 2-D table, and it answers 20,000 on an input whose true minimum is 26,000. Not an approximation, not a rounding error - 20,000 corresponds to no way of bracketing the product at all.

Where this sits

Day 33 asked "what do I do with element i", Day 34 asked "do I take this item", Day 35 asked "does the subsequence end here". All three walk forwards through a prefix. Today the subproblem stops being a prefix: an interval DP asks where does this range split, and a tree DP asks what does this subtree report to its parent. Both recurrences are two or three lines. What is easy to get wrong is the order the table is filled and the number of values each subproblem has to report - and both mistakes are silent.

The cheapest way to multiply four matrices

Matrix multiplication is associative: (AB)C and A(BC) produce the same matrix. They do not cost the same. Multiplying a p x q by a q x r takes p*q*r scalar multiplications, so with shapes 40x20, 20x30, 30x10, 10x30 the bracketing ((A(BC))D) costs 26,000 and the worst legal bracketing costs 69,000 - the same answer, at 2.65 times the price.

Trying every bracketing is hopeless: the count is a Catalan number. So dp[i][j], the cheapest way to multiply matrices i through j, asks exactly one question. At the very top, a product of i..j is a product of two things: i..k and k+1..j. Which k?

dp[i][j] = min over k of  dp[i][k] + dp[k + 1][j] + rows(i) * cols(k) * cols(j)

Both sub-intervals are strictly shorter than i..j. That is not a cute observation, it is the fill order:

for length in range(2, n + 1):            # the outer loop is LENGTH
    for i in range(n - length + 1):
        j = i + length - 1
        dp[i][j] = float('inf')
        for k in range(i, j):
            cost = dp[i][k] + dp[k + 1][j] + dims[i] * dims[k + 1] * dims[j + 1]
            if cost < dp[i][j]:
                dp[i][j] = cost
                split[i][j] = k

Now go back to the broken version at the top of this article. dp[i][j] reads dp[k+1][j], and k+1 > i, so it is reading a row below the current one - a row the i-then-j loops have not reached yet. Those cells still hold their initial 0. Several multiplications get priced at zero, the minimum comes out too small, and Python reports nothing at all. Filling by interval length makes that impossible, because "shorter" and "already computed" become the same statement.

split[i][j] is the usual byproduct: recursing through it rebuilds ((A(BC))D), the actual bracketing, not just its price.

LeetCode 312 - Burst Balloons

The task. A row of balloons each carries a number. You pop them one at a time; popping a balloon earns the product of its own number and the numbers of its two neighbours at that moment, and once it is gone its neighbours become adjacent to each other. A missing neighbour past the end of the row counts as 1. Pop all of them and maximise the total.

Input / output. A list of integers; return the maximum number of coins.

Example. [3, 1, 5, 8] gives 167: pop 1 for 3*1*5 = 15, then 5 for 3*5*8 = 120, then 3 for 1*3*8 = 24, then 8 for 1*8*1 = 8.

Constraints. At most 300 balloons, values up to 100. 300 kills any enumeration of orders - 4! is 24, 300! is not a number you can loop over - and it is exactly the size that says "an O(n^3) interval DP is expected".

leetcode.com/problems/burst-balloons

Pad the row with a 1 at each end so the boundary needs no special case. Then the instinctive move is to ask which balloon pops first inside the interval, earn its coins, and recurse on the two sides. Try it:

return max(a[k - 1] * a[k] * a[k + 1] + go(i, k - 1) + go(k + 1, j)
           for k in range(i, j + 1))

It returns 98. Not an exception - 98. The two halves are not independent: once k is gone, the left half's right-hand neighbour is a balloon owned by the right half, so the coins the left half can still earn depend on what the right half does. The recurrence is asking about subproblems that do not exist.

Flip the question to which balloon pops last in the open interval (i, j) and everything snaps into place. If k is last, then by the time it pops, everything strictly between i and j is already gone, so its two neighbours are exactly i and j - walls that never move, no matter what happens inside the halves.

for k in range(i + 1, j):
    cand = dp[i][k] + dp[k][j] + a[i] * a[k] * a[j]

167, agreeing with brute force over all 24 orders, and the choice table replays the real popping order [1, 5, 3, 8].

LeetCode 1547 - Minimum Cost to Cut a Stick

The task. A wooden stick of length n has to be cut at every position in a given list. Cutting a piece costs the current length of that piece, and you may perform the cuts in any order. Minimise the total cost.

Input / output. The length n and the list of cut positions; return the minimum cost.

Example. n = 7 with cuts [1, 3, 4, 5]: doing them in the order given costs 20, the best order costs 16.

Constraints. n can be up to 10^6 but there are at most 100 cuts. That gap is the whole hint: the table must be indexed by cut positions (m <= 102, so O(m^3) is trivial), never by the stick's length.

leetcode.com/problems/minimum-cost-to-cut-a-stick

This one is the mirror image of the balloons, and it is worth sitting with for a second. Here the first cut is the separable one: it costs the whole length of the current piece regardless of what has happened elsewhere, and it splits the piece into two that never interact again. So "which one first" decomposes here and "which one last" decomposes there. The lesson is not a rule to memorise - it is a question to ask every time: which choice makes the two sides independent?

Add the two ends as fake cuts, sort, and it is matrix chain with a different cost term:

dp[i][j] = min(dp[i][k] + dp[k][j] for k in range(i + 1, j)) + pts[j] - pts[i]

LeetCode 516 - Longest Palindromic Subsequence

The task. Given a string, return the length of its longest subsequence that reads the same forwards and backwards. Characters may be skipped; the ones kept must keep their order.

Input / output. A string; return an integer length.

Example. 'character' gives 5, for 'carac'.

Constraints. Up to 1000 characters, lower-case letters. A million-cell O(n^2) table is fine; anything enumerating subsequences is not.

leetcode.com/problems/longest-palindromic-subsequence

As an interval DP it is four lines: equal ends contribute 2 and shrink inwards, unequal ends drop one side or the other. But it also has a one-line solution that needs no new code - the longest palindromic subsequence of s is the longest common subsequence of s and s reversed, which is yesterday's table. Both give 5 on 'character', and the interval version additionally hands back the string itself.

LeetCode 337 - House Robber III

The task. The houses are arranged in a binary tree and each one holds some money. Two directly connected houses cannot both be robbed. Maximise what you take.

Input / output. The root of a binary tree of integers; return the maximum total.

Example. Root 3, left child 2 whose right child is 3, right child 3 whose right child is

  1. The answer is 7: the two leaves 3 and 3, plus the 1 - never a parent together with its child.

Constraints. Up to 10^4 nodes, values 0 to 10^4. Ten thousand nodes is far past Python's default recursion limit of 1000 once the tree degenerates into a path, which is the trap the constraint quietly sets up.

leetcode.com/problems/house-robber-iii

The natural thing is for every node to report one number: the best its subtree can give. Write it and it returns 12 instead of 7, with no complaint.

def go(node):
    if node is None:
        return 0
    below = go(node.left) + go(node.right)
    return max(node.val + below, below)     # one number: not enough state

The parent needs to know something that single number does not carry: was the child itself used? Without it, and with positive values, max always prefers node.val + below, so every node is taken - parents and children together. 12 is just the sum of everything, wearing a DP costume.

Two numbers per node make the states independent again:

robbed  = node.val + ls + rs           # take me: children must be skipped
skipped = max(lr, ls) + max(rr, rs)    # skip me: children are free

It is the same lesson as Day 35's dp[i] that must end at i: the state has to carry exactly the fact the next decision depends on. The same shape appears in LeetCode 124, maximum path sum, where a node returns its best single downward arm but scores the path that bends through it - what a node returns is not what a node scores - and in tree diameter, the unweighted version of that same pair.

Tree knapsack, and a sum that is not cubic

Picking courses where a course may only be taken together with its prerequisite arranges the items in a tree. dp[v][t] is the best value from v's subtree taking exactly t items, and children are merged one at a time, each merge a tiny knapsack:

for t in range(min(size[v], budget), 0, -1):
    for u in range(1, min(size[c], budget - t) + 1):
        nd[t + u] = max(nd[t + u], dp[t] + cdp[u])

That double loop inside a recursion over n nodes looks cubic and is not. Those two min(...) bounds are not micro-optimisations: the work at a node is exactly size(child) * size(merged so far), which counts the pairs of nodes whose lowest common ancestor is that node. Every pair in the tree has exactly one lowest common ancestor, so summed over the whole tree the total is C(n, 2) - 15 for six nodes, which the code counts and asserts rather than claims.

The depth trap

Every tree DP is a post-order traversal, and a recursive post-order dies on a path-shaped tree of 60,000 nodes. This failure at least is loud - RecursionError - but it arrives in production, not on the sample input. Push the nodes onto a stack and you get parents before children; reverse that and you get children before parents, which is what the DP needs:

order, stack = [], [root]
while stack:
    v = stack.pop()
    order.append(v)
    stack.extend(children[v])
for v in reversed(order):
    total[v] = value[v] + sum(total[c] for c in children[v])

Why this matters later

Splitting on a range rather than on the next element is how parsers work: the CYK algorithm is this exact triangle, and optimal binary search trees are matrix chain with probabilities. The tree version is even closer to home for anyone touching machine learning - a backward pass is a post-order traversal where each node reports a tuple to its parent, and the "one number is not enough state" bug is the same one you hit when a layer forgets to carry the piece of information the next layer's gradient depends on. Query planners join relations in whatever order is cheapest, which is matrix chain with different arithmetic.

Tomorrow the subproblem stops being an interval too, and starts being a set - the states become bitmasks, which is how the travelling salesman problem gets solved exactly for small n.
