100 Days of Python - day 26

Yesterday I could find a pattern in a text. Today I want to answer two questions yesterday's algorithms cannot touch: what does this corpus repeat - nobody hands you a pattern - and which of ten thousand patterns just fired - you cannot afford ten thousand passes.

Both of day 25's algorithms preprocess the pattern and then read the text. That is the right shape when the text is a stream and the pattern is known in advance. Today's two structures invert one assumption each. A suffix array preprocesses the text, so questions can be asked later, cheaply, including questions that have no pattern at all. Aho-Corasick preprocesses all the patterns at once, so the text is read a single time regardless of how many there are.

The array is just sorted starting positions

A suffix array is the sorted order of every suffix of a string, stored as the positions they start at. For banana the suffixes sort to a, ana, anana, banana, na, nana, so the array is [5, 3, 1, 0, 4, 2] - six integers, not six substrings, so the whole structure is O(n) memory.

The definition is also a one-liner, and it is a trap:

def suffix_array_naive(s):
    return sorted(range(len(s)), key=lambda i: s[i:])

This is correct and O(n² log n): every comparison can read an entire suffix, and s[i:] materialises n substrings on the way. Prefix doubling removes both problems. Replace each character by its rank; then the first 2k characters of suffix i are exactly the pair (rank[i], rank[i+k]), because the second half of suffix i is the first k characters of suffix i+k, whose rank we already know.

def suffix_array(s):
    n = len(s)
    rank, k = [ord(c) for c in s], 1
    sa = list(range(n))
    while True:
        key = lambda i: (rank[i], rank[i + k] if i + k < n else -1)
        sa.sort(key=key)
        new = [0] * n
        for a, b in zip(sa, sa[1:]):
            new[b] = new[a] + (1 if key(a) < key(b) else 0)
        rank = new
        if rank[sa[-1]] == n - 1:      # all ranks distinct -> order is final
            return sa
        k *= 2

Comparing a pair of small integers is O(1) however long the suffixes behind it are, and k doubles each round, so there are log n rounds of one sort: O(n log² n), or O(n log n) if you swap the comparison sort for day 22's counting sort. On banana the ranks go [1,0,2,0,2,0] → [2,1,3,1,3,0] → [3,2,5,1,4,0] and stop, because that last row has no ties left. The termination test is the tie test: while two suffixes share a rank, the algorithm has not yet looked at enough characters to separate them.

LCP: the array that makes it useful

Sorted positions answer "where". The array that answers everything else is lcp[i]: how many leading characters the neighbours sa[i-1] and sa[i] share. For banana it is [0, 1, 3, 0, 0, 2]. Comparing every adjacent pair from scratch is O(n²); Kasai's algorithm does it in O(n) with one observation.

def lcp_kasai(s, sa):
    n = len(s)
    rank = [0] * n
    for i, p in enumerate(sa):
        rank[p] = i
    lcp, h = [0] * n, 0
    for i in range(n):                 # walk the TEXT, not the array
        if rank[i] == 0:
            h = 0
            continue
        j = sa[rank[i] - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[rank[i]] = h
        if h:
            h -= 1                     # the whole proof lives on this line
    return lcp

Suffix i+1 is suffix i minus its first character, so if suffix i shared h characters with its neighbour, suffix i+1 shares at least h-1 with its neighbour. h therefore drops by at most one per step and rises at most n times in total, which bounds the inner loop globally rather than per iteration - the same amortised argument that bounded KMP's fall-backs yesterday.

Two things fall out immediately. Because the array is sorted, the common prefix of any two suffixes is the minimum lcp between them, so the largest entry is the longest repeated substring: ana in banana, issi in mississippi. And a query becomes two binary searches (day 23), because every suffix starting with ana must be contiguous:

lo, hi = sa_range(s, sa, 'ana')        # -> (1, 3), so two occurrences
occurrences = sorted(sa[lo:hi])        # -> [1, 3]

Each of the O(log n) probes reads only m characters, so a query is O(m log n), counting is end - lo in O(1), and a miss ('x') simply produces an empty range. The trade against KMP is explicit: KMP re-reads the text for every new pattern; a suffix array reads it once and then never again.

The question with no pattern: deduplicating a corpus

Here is why you would build this rather than a hash index. Training-corpus deduplication asks for every block of at least min_len characters that occurs more than once, and you do not know in advance what those blocks are. A run of lcp >= min_len is exactly such a block, and its length is the run's minimum.

Written that way, the function is also useless. On my two-document example it reports 68 spans and claims a saving of 984% of a 214-character input - because a repeated block and every one of its shifted copies are all reported separately. he cat sat. is the cat sat. with the first character removed, and both are counted, and so is e cat sat., and so on.

The fix is one line: keep a run only if its occurrences are not all preceded by the same character.

group = sa[i - 1:j]
left = {text[p - 1] if p else None for p in group}
if len(left) > 1:                      # left-diverse: a maximal repeat
    out.append((len(group), text[group[0]:group[0] + run]))

A span whose occurrences share a left neighbour can always grow one character leftwards, so it is not a maximal repeat - it is somebody else's tail. With the test, the same input reports two spans and a saving of 42.1%, and the pipeline is still two linear passes over the text. That is not an optimisation, it is correctness: without it, a dedup report counts the same passage many times over. This is the structure behind the work on deduplicating training data, where removing repeated passages lowered both loss and memorisation.

Aho-Corasick is yesterday's failure function, grown on a tree

Now the other inversion. Running KMP k times costs O(k · n) and reads the text k times, which is the wrong shape for a banned-phrase list. Aho-Corasick puts all the patterns in one trie - shared prefixes stored once - and then adds a fail link from each node to the node spelling the longest proper suffix of it that is still in the trie. That is word for word day 25's failure function, with a tree in place of a string.

while q:
    v = q.popleft()
    for ch, u in self.goto[v].items():
        f = self.fail[v]
        while f and ch not in self.goto[f]:
            f = self.fail[f]
        self.fail[u] = self.goto[f].get(ch, 0)
        self.out[u] += self.out[self.fail[u]]   # 'he' also ends inside 'she'
        q.append(u)

The BFS order matters: fail[v] is always shallower than v, so it is already computed when needed. The out inheritance is the line that is easy to omit and silently loses matches - arriving at she also completes he, and find_all('ushers') must return [(3, 'she'), (3, 'he'), (5, 'hers')]. And the sanity check that these really are one idea: build the automaton on a single pattern, the trie degenerates into a chain, and the fail depths equal kmp_failure(pattern) exactly.

Matching is then one pass in which the cursor never moves backwards. On a 126-character sample with five patterns, five KMP passes spend 675 character comparisons; one Aho-Corasick pass spends 159 transitions over a 15-node automaton and finds the same 27 hits. The cost is O(n + total pattern length + matches) and does not depend on k.

Streaming stop strings, and when not to use this

Day 25's streaming problem returns, now with three stop strings. A server may not emit a character that could turn out to be the opening of a stop string, so it holds text back. With one pattern the hold-back was "how much of the pattern currently matches"; with k patterns the naive version asks that of every pattern and takes the maximum. In the automaton the number is already sitting there:

hold = self.ac.depth[self.state]       # <- the whole trick
if len(self.buf) > hold:
    safe += self.buf[:len(self.buf) - hold]
    self.buf = self.buf[len(self.buf) - hold:]

The state spells the longest prefix of any pattern that the tail currently matches, so its depth is the hold-back, and k stop strings cost the same per character as one. Feeding ["The answer", " is 42.<", "/", "s> and more"] emits The answer is 42., holding one character back, then two, then cutting cleanly at </s>.

And the honest part: sglang does not do this, and is right not to. It clips the tail it re-checks to stop_str_max_len + 1 characters and runs a plain substring search per stop string, O(k · L²) per step - about 162 character comparisons for two stop strings, which is noise next to a forward pass. Bounding the input instead of improving the algorithm is a perfectly good engineering decision whenever you can prove the bound. Aho-Corasick earns its keep at the other end of k: PII filters, guardrail lists and banned-phrase lists with thousands of entries, where one pass per entry stops being free.

The LeetCode problems

LC 1032, Stream of Characters is the automaton with the buffer deleted. Letters arrive forever; the object keeps one integer, steps it, and returns whether out[state] is non-empty. The tempting solution - a trie of reversed words plus a growing buffer, re-walked on each query - stores history that the state already summarises.

LC 1044, Longest Duplicate Substring is a deliberate rerun of yesterday. Day 25 solved it with binary search over the length plus a rolling hash: a solution that can in principle return a wrong answer, kept honest only by its verification step. Today it is the largest lcp entry - exact, no hashing, no randomness, because sorting has already placed every repeat next to its twin. The price is the O(n log n) preprocessing; what you buy is exactness and one index that keeps answering other questions.

Complexity

suffix_array_naive (the definition)      O(n^2 log n) time    O(n^2) space
suffix_array (prefix doubling)           O(n log^2 n)         O(n)
  with a counting sort                   O(n log n)           O(n)
lcp_kasai                                O(n)                 O(n)
sa_range / sa_count (one pattern)        O(m log n)           O(1)
longest_repeated_substring               O(n log^2 n)         O(n)
duplicate_spans / dedup_report           O(n log^2 n)         O(n)
Aho-Corasick build                       O(L)                 O(L * sigma)
Aho-Corasick search                      O(n + matches)       O(L * sigma)
k separate KMP passes                    O(k * n + L)         O(L)
streaming multi-stop, per character      O(1) amortised       O(L)

n = text length, m = pattern length, k = number of patterns, L = total pattern length.

Why this matters later

Both structures come back as infrastructure rather than as algorithms. The suffix array is the exact version of the near-duplicate detection that MinHash and SimHash approximate, and corpus deduplication is one of the few preprocessing steps with a measurable effect on model quality. Aho-Corasick is the shape of every multi-pattern filter in a serving stack: banned phrases, PII redaction, tool-call delimiters, structured-output guards - anywhere a stream must be checked against a dictionary that keeps growing while the per-token budget does not.
