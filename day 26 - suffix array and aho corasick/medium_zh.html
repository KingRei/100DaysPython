100 Days of Python - day 26

昨天我可以在一份文字裡找到某個 pattern。今天想回答的是兩個昨天碰不到的問題：這份語料重複了什麼（根本沒有人給你 pattern），以及這一萬個 pattern 剛剛哪一個出現了（不可能掃一萬遍）。

day 25 的兩個演算法都是先前處理 pattern，再讀文字。文字是串流、pattern 事先已知時，這個形狀是對的。今天的兩個結構各推翻其中一個假設：suffix array 前處理的是文字，所以問題可以事後再問，而且很便宜，包括那些根本寫不成 pattern 的問題；Aho-Corasick 前處理的是全部的 pattern，所以不管有幾個，文字只讀一遍。

這個陣列只是排序好的起始位置

suffix array 就是一個字串所有後綴排序後的順序，存的是它們的起始位置。banana 的後綴排序後是 a、ana、anana、banana、na、nana，所以陣列是 [5, 3, 1, 0, 4, 2] — 六個整數，不是六個字串，整個結構是 O(n) 記憶體。

照定義寫也是一行，而這一行是個陷阱：

def suffix_array_naive(s):
    return sorted(range(len(s)), key=lambda i: s[i:])

它完全正確，也完全是 O(n² log n)：每次比較都可能讀完整個後綴，而且 s[i:] 會實際切出 n 個子字串。Prefix doubling 一次解決兩個問題：把字元換成排名，那麼後綴 i 的前 2k 個字元就剛好是一對排名 (rank[i], rank[i+k]) — 因為後綴 i 的後半段，就是後綴 i+k 的前 k 個字元，而它的排名我們已經知道了。

def suffix_array(s):
    n = len(s)
    rank, k = [ord(c) for c in s], 1
    sa = list(range(n))
    while True:
        key = lambda i: (rank[i], rank[i + k] if i + k < n else -1)
        sa.sort(key=key)
        new = [0] * n
        for a, b in zip(sa, sa[1:]):
            new[b] = new[a] + (1 if key(a) < key(b) else 0)
        rank = new
        if rank[sa[-1]] == n - 1:      # all ranks distinct -> order is final
            return sa
        k *= 2

一對小整數比大小是 O(1)，不管後面那串有多長；而 k 每輪加倍，所以只有 log n 輪、每輪一次排序，總共 O(n log² n)（把比較排序換成 day 22 的 counting sort 就是 O(n log n)）。banana 的排名走 [1,0,2,0,2,0] → [2,1,3,1,3,0] → [3,2,5,1,4,0] 就停了，因為最後一列已經沒有並列。終止條件就是並列條件：只要還有兩個後綴排名相同，就代表看的字元還不夠多，分不出來。

LCP：讓這個陣列真正有用的那一半

排序好的位置回答的是「在哪裡」。回答其他所有問題的是 lcp[i]：相鄰的 sa[i-1] 與 sa[i] 共用幾個開頭字元。banana 的是 [0, 1, 3, 0, 0, 2]。一對一對重算是 O(n²)；Kasai 只靠一個觀察就做到 O(n)。

def lcp_kasai(s, sa):
    n = len(s)
    rank = [0] * n
    for i, p in enumerate(sa):
        rank[p] = i
    lcp, h = [0] * n, 0
    for i in range(n):                 # walk the TEXT, not the array
        if rank[i] == 0:
            h = 0
            continue
        j = sa[rank[i] - 1]
        while i + h < n and j + h < n and s[i + h] == s[j + h]:
            h += 1
        lcp[rank[i]] = h
        if h:
            h -= 1                     # the whole proof lives on this line
    return lcp

後綴 i+1 就是後綴 i 砍掉第一個字元，所以如果後綴 i 與它的鄰居共用 h 個字元，後綴 i+1 與它自己的鄰居至少共用 h−1 個。於是 h 每步最多掉一格、整趟最多漲 n 次，內層迴圈是被全域攤還掉的，而不是每次迭代各自有界 — 跟昨天 KMP 回退次數的論證是同一套。

有兩件事馬上跟著出來。因為陣列已排序，任兩個後綴的共同開頭等於它們之間所有 lcp 的最小值，所以最大的那一格就是最長重複子字串：banana 是 ana、mississippi 是 issi。而查詢則變成兩次二分搜尋（day 23），因為所有以 ana 開頭的後綴一定連在一起：

lo, hi = sa_range(s, sa, 'ana')        # -> (1, 3), so two occurrences
occurrences = sorted(sa[lo:hi])        # -> [1, 3]

O(log n) 次探測、每次只讀 m 個字元，所以一次查詢是 O(m log n)；要數次數就是 end - lo，O(1)；查不到（'x'）就得到一段空區間。與 KMP 的取捨很明確：KMP 每來一個新 pattern 就要重讀一次文字，suffix array 讀一次之後再也不碰。

沒有 pattern 的那種問題：語料去重

這才是為什麼要建這個結構、而不是建一個雜湊索引。訓練語料去重要問的是「所有長度 ≥ min_len 且出現超過一次的區塊」，而你事先不知道那些區塊長什麼樣。lcp 連續 ≥ min_len 的一段，剛好就是這種區塊，長度就是那段的最小值。

只寫到這裡，這個函式其實不能用。在我那份兩篇文件的例子上，它回報了 68 個區塊，並宣稱在 214 個字元裡省下了 984% — 因為一個重複區塊和它所有的位移副本都被分別回報了。he cat sat. 只是 the cat sat. 砍掉第一個字元，兩個都算，e cat sat. 也算，以此類推。

修正只有一行：只有當一段的所有出現位置的左鄰字元不全相同時才留下來。

group = sa[i - 1:j]
left = {text[p - 1] if p else None for p in group}
if len(left) > 1:                      # left-diverse: a maximal repeat
    out.append((len(group), text[group[0]:group[0] + run]))

如果一段的每次出現左邊都是同一個字元，那它永遠可以再往左長一格，所以它不是極大的重複，只是別人的尾巴。加上這行之後，同一份輸入只回報 2 個區塊、省下 42.1%，而整條流程仍然只掃文字兩遍。這不是效能優化，是正確性：沒有它，去重報告會把同一段重複算很多次。真實世界的訓練資料去重論文用的就是這個結構，把重複段拿掉可以同時降低 loss 與記憶效應。

Aho-Corasick 就是昨天的 failure function 長在樹上

換另一個方向。跑 k 次 KMP 是 O(k · n)，而且文字要讀 k 遍，對一份禁詞清單來說形狀完全不對。Aho-Corasick 把所有 pattern 放進一棵 trie（共用前綴只存一份），再替每個節點加一條 fail link，指向「這個節點拼出的字串的最長真後綴中，還留在 trie 裡的那一個」。這跟 day 25 的 failure function 一字不差，只是把字串換成樹。

while q:
    v = q.popleft()
    for ch, u in self.goto[v].items():
        f = self.fail[v]
        while f and ch not in self.goto[f]:
            f = self.fail[f]
        self.fail[u] = self.goto[f].get(ch, 0)
        self.out[u] += self.out[self.fail[u]]   # 'he' also ends inside 'she'
        q.append(u)

BFS 的順序是關鍵：fail[v] 一定比 v 淺，所以用到它的時候它已經算好了。而 out 的繼承是最容易漏、漏了又不會報錯的一行 — 走到 she 的同時 he 也結束了，find_all('ushers') 必須回傳 [(3, 'she'), (3, 'he'), (5, 'hers')]。想確認這兩者真的是同一個東西，可以拿單一個 pattern 建自動機：trie 退化成一條鏈，每個節點的 fail 深度完全等於 kmp_failure(pattern)。

比對階段就是一遍掃過去，指標從不回頭。在一段 126 字元的文字上放 5 個 pattern：跑 5 次 KMP 花掉 675 次字元比較；一次 Aho-Corasick 花 159 次轉移、自動機 15 個節點，找到同樣的 27 個命中。成本是 O(n + 所有 pattern 長度 + 命中數)，與 k 無關。

串流的 stop 字串，以及什麼時候不該用它

day 25 的串流問題回來了，這次有三個 stop 字串。伺服器不能送出「有可能是 stop 字串開頭」的字元，所以要扣住一些文字。一個 pattern 時，扣住的量是「目前配到 pattern 的多少」；k 個 pattern 時，天真作法要對每個 pattern 各問一次再取最大。但在自動機裡，這個數字本來就在那了：

hold = self.ac.depth[self.state]       # <- the whole trick
if len(self.buf) > hold:
    safe += self.buf[:len(self.buf) - hold]
    self.buf = self.buf[len(self.buf) - hold:]

狀態拼出的正是「尾巴目前配上的、任一 pattern 的最長前綴」，所以它的深度就是 hold-back，k 個 stop 字串每個字元的成本和一個一樣。餵進 ["The answer", " is 42.<", "/", "s> and more"]，它送出 The answer is 42.，中間先扣一個字元、再扣兩個，最後在 </s> 乾淨切斷。

還有誠實的部分：sglang 沒有這樣做，而它是對的。它把要重驗的尾巴裁到 stop_str_max_len + 1 個字元，然後每個 stop 字串各做一次普通子字串搜尋，每步 O(k · L²) — 兩個 stop 字串大約 162 次字元比較，跟一次 forward pass 相比根本是雜訊。只要你能證明那個上界，限制輸入本來就是「改進演算法」以外一個完全合理的工程選擇。Aho-Corasick 真正划算的是 k 很大的另一端：PII 過濾、guardrail、上千條的禁詞清單，那時候「每條掃一遍」就不再免費了。

LeetCode

LC 1032 Stream of Characters 就是把 buffer 拿掉的自動機。字母永遠一個一個來，物件只保存一個整數，走一步、回傳 out[state] 是否非空。那個看起來很自然的解法 — 反轉字典建 trie，再配一個越長越長的 buffer 每次重走 — 存的是狀態早就摘要好的歷史。

LC 1044 Longest Duplicate Substring 是刻意重跑昨天的題目。day 25 的解法是對長度二分搜尋加 rolling hash：那個解法原則上可能給錯答案，全靠最後的 verify 步驟撐著。今天它就是 lcp 最大的那一格 — 精確、沒有雜湊、沒有機率，因為排序已經把每個重複和它的雙胞胎排在一起了。代價是 O(n log n) 的前處理；換來的是精確，以及同一份索引可以繼續回答別的問題。

複雜度

suffix_array_naive (照定義)              O(n^2 log n) time    O(n^2) space
suffix_array (prefix doubling)           O(n log^2 n)         O(n)
  換成 counting sort                     O(n log n)           O(n)
lcp_kasai                                O(n)                 O(n)
sa_range / sa_count (單一 pattern)       O(m log n)           O(1)
longest_repeated_substring               O(n log^2 n)         O(n)
duplicate_spans / dedup_report           O(n log^2 n)         O(n)
Aho-Corasick 建表                        O(L)                 O(L * sigma)
Aho-Corasick 比對                        O(n + matches)       O(L * sigma)
k 次獨立的 KMP                           O(k * n + L)         O(L)
串流多重 stop，每字元                    O(1) amortised       O(L)

n = 文字長度，m = pattern 長度，k = pattern 個數，L = 所有 pattern 長度總和。

之後會用到的地方

這兩個結構之後都是以基礎設施的身分出現，而不是以演算法的身分。suffix array 是 MinHash、SimHash 那類近似重複偵測的精確版，而語料去重是少數幾個對模型品質有可量測影響的前處理步驟。Aho-Corasick 則是 serving 端每一種多模式過濾的形狀：禁詞、PII 遮蔽、tool-call 分隔符、結構化輸出的守門 — 只要有一份會不斷長大的字典要拿去檢查串流，而每個 token 的預算不會跟著長大。

LeetCode 616 - Add Bold Tag in String（給字串加上粗體標籤）

題目。 給一個字串 s 和一組 words，把 s 裡面所有出現在 words 中的子字串用 <b> 與 </b> 包起來。重疊或相鄰的粗體區段要合併成同一對標籤，而且標籤數量要最少。

輸入／輸出。 輸入 s 與 words，輸出加上標籤後的字串。

範例。 s = "abcxyz123"、words = ["abc","123"] → "<b>abc</b>xyz<b>123</b>"。 若 s = "aaabbb"、words = ["aa","b"]，命中的區間重疊又相連，答案是 "<b>aaabbb</b>"。

限制。 1 <= len(s) <= 1000、0 <= len(words) <= 100，每個 word 最長 1000 個字元，內容是 小寫字母與數字。（同一題在 LeetCode 758《Bold Words in String》又出現一次。）用一次 Aho-Corasick 掃出所有命中位置、再做區間合併，就是最乾淨的寫法。

LeetCode 1032 - Stream of Characters（字元流）

題目。 做一個 StreamChecker，建構時給一組 words。之後字元會透過 query(letter) 一個一個 進來，每次呼叫都要回答：目前收到的整串字元裡，有沒有某個後綴剛好等於某個 word。

輸入／輸出。 建構子吃 words，每次 query 回傳布林值。

範例。 words = ["cd","f","kl"]，依序 query a、b、c、d、e、f，回傳 False, False, False, True, False, True —— 在 d 是 True 因為串流結尾是 "cd"，在 f 是 True 因為結尾是 "f"。

限制。 1 <= len(words) <= 2000，每個 word 長度 1..200，最多 4 * 10^4 次查詢。因為每次 只多一個字元，答案必須*增量*維護 —— 那就是 Aho-Corasick 的自動機狀態，或是一棵把單字反過來存的 trie。

LeetCode 1044 - Longest Duplicate Substring（最長重複子字串）

題目。 找出在 s 中至少出現兩次的最長子字串；兩次出現可以重疊。回傳其中任何一個， 若沒有任何子字串重複就回傳空字串。

輸入／輸出。 輸入一個字串，輸出一個字串。

範例。 s = "banana" → "ana"（出現在索引 1 與 3，而且是重疊的）；s = "abcd" → ""。

限制。 2 <= len(s) <= 3 * 10^4，小寫英文字母。「有沒有長度 L 的重複子字串」對 L 是單調 的，所以標準解法是對 L 二分搜尋、每次用 Rabin-Karp rolling hash 回答；或者完全不用隨機性， 直接從 suffix array 加上它的 LCP 陣列把答案讀出來。
