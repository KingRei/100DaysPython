讓 Dijkstra 算錯的那一行

程式碼：day 17 on GitHub

100 Days of Python - day 17

昨天的 heap_greedy 骨架裡藏了一句沒有明講的理由：任何通往這個節點的其他路線，都必須經過 還留在 heap 裡的某個節點，而那個節點的距離已經不小於它，再多接幾條邊只會更長。 Dijkstra 的所有保證都建立在這句話上，而這句話建立在一個前提上——多加一條邊，不會讓路徑變短。

只要權重可以是負的，這句話就不成立了。而真正麻煩的是：Dijkstra 不會告訴你。 沒有例外、沒有無窮迴圈、沒有警告，它就是回傳一個長得跟答案一模一樣的數字。

三個節點的圖，邊是 A->B = 5、A->C = 2、B->C = -10，Dijkstra 給你 C = 2。 正確答案是走 B 的 -5。今天整篇文章都是為了處理這件事。

誰都不定案，全部都放鬆

Bellman-Ford 對「該先相信哪個節點」的回答是：一個都不信。 既然沒辦法知道正確的順序，那就不要挑——把每一條邊都放鬆一次，然後重複。

def bellman_ford(n, edges, src):
    dist, parent = [INF] * n, [-1] * n
    dist[src] = 0
    for _ in range(n - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] + w < dist[v]:       # the same line Dijkstra uses
                dist[v] = dist[u] + w
                parent[v] = u
                changed = True
        if not changed:                     # converged early
            break

那行 relaxation 跟昨天的一字不差。relaxation 本身從來不需要非負權重，需要非負權重的是 settle（定案）這個動作。

為什麼跑 n - 1 輪？因為有一個很好記也很好相信的不變量： 跑完第 r 輪之後，所有「最多用 r 條邊」的最短路徑都已經是正確的。 第 1 輪處理一條邊到得了的、第 2 輪把它們再往外接一條，以此類推。 只要沒有負環，最短路徑就不會重複經過節點，因此最多用 V-1 條邊。 迴圈次數不是拍腦袋來的，它就是證明本身。

拿上面那張圖跑一次，盯著 B 看。第 1 輪它是 6，直接走 A->B；第 2 輪掉到 2，因為 A->D->C->B 只要 7 - 3 - 2。Dijkstra 會在 6 的時候把 B 定案，之後再也不回頭。 Bellman-Ford 沒有「定案」這個概念，所以它活得下來。

代價就寫在迴圈裡：O(VE)，對比 Dijkstra 的 O(E log V)。

只重算有變動的部分

那些工作大部分是白做的。邊 u -> v 只有在 dist[u] 剛剛變小的時候才可能放鬆成功； 上游沒動的情況下再掃一次，不可能有任何幫助。SPFA（Shortest Path Faster Algorithm） 就是把這個觀察寫成一個 queue。

def spfa(n, adj, src):
    dist = [INF] * n
    dist[src] = 0
    q, inq = deque([src]), [False] * n
    inq[src] = True
    while q:
        u = q.popleft(); inq[u] = False
        for v, w in adj[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                if not inq[v]:              # queue only what changed
                    q.append(v); inq[v] = True
    return dist

答案跟 Bellman-Ford 完全相同；在這張五個節點的圖上它只 pop 了 7 次， 而 Bellman-Ford 把 10 條邊掃了四輪。但也要看清楚什麼沒有改善： 最壞情況仍然是 O(VE)，而且有專門為了整 SPFA 而設計的圖能把它打回原形。 這是一個你可以享受、但不能倚賴的常數項優化。

當答案是負無限大

把那張圖改一個權重——E->C 從 7 改成 1——迴圈 B -> E -> C -> B 的總和就是 -4 + 1 - 2 = -5。繞一圈便宜 5，再繞一圈再便宜 5。這時候根本不存在最短路徑，下界是負無限大。

Bellman-Ford 用同一套機制免費偵測到這件事。V-1 輪已經涵蓋了所有不重複經過節點的路徑， 所以就再跑第 V 輪：如果還有任何距離變小，那條讓它變小的路徑一定重複經過了某個節點， 也就是說它繞了一個總權重為負的環。

for u, v, w in edges:               # one extra round
    if dist[u] + w < dist[v]:
        return dist, True           # negative cycle reachable from src

如果要把環本身印出來、而不只是回報有環，就從那個還在變小的節點沿著 parent 往回走 V 步。 走這麼多步一定會落在環裡面，接著再沿著環走一圈回到起點就好。

值得一提的是，這個「失敗情況」常常才是真正的目的。把匯率取負對數當成邊權， 匯率相乘就變成權重相加，而一個總權重為負的環，就是一串做完之後錢變多的交易。 Bellman-Ford 不是在回報錯誤，它是在回報套利機會。

一次算完所有點對

換一個問題：不是「所有東西離 A 多遠」，而是「所有東西離所有東西多遠」。 從每個節點各跑一次 Bellman-Ford 是 O(V^2 E)。Floyd-Warshall 用三層迴圈就全部解決。

它的 DP 維度很容易被忽略：允許出現在路徑中間的節點有哪些。 跑完第 k 階段之後，dist[i][j] 的意思是「從 i 到 j、中間節點全部取自 {0..k} 的最便宜路徑」。 放行節點 k 只給你兩個選擇——用或不用——所以更新只有一行。

for k in range(n):                  # k MUST be the outer loop
    for i in range(n):
        for j in range(n):
            if dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]

整段唯一的細節就是迴圈順序，而且值得講白：k 不是為了對稱才擺進來的第三個 index， 它是這個 DP 的階段，i 和 j 只是這個階段要更新的格子。 如果寫成 for i / for j / for k，第 k 階段會在自己還沒算完之前就被讀取—— dist[i][k] 在半成品的狀態下被拿去用。

不會當掉。表格照樣填滿、程式照樣回傳，而在我這張五個節點的圖上， 二十五格裡有三格靜靜地偏大。這才是要怕的失效模式：不是會噴例外的那種，是會回傳的那種。

Floyd-Warshall 不需要為負邊做任何特別處理，而且它也能偵測負環： 迴圈跑完之後，只要有 dist[i][i] < 0，就代表從 i 出發繞一圈回來的成本小於零。

面試版本：LeetCode 787

Cheapest Flights Within K Stops. 給定航班與票價，找出從 src 到 dst、 最多轉機 k 次的最便宜路線。多出來的那個限制，就是讓很多人跑去改 Dijkstra 然後陷進去的原因。

換個方式讀這個限制就好。最多 k 次轉機 = 最多 k+1 個航班 = 最多 k+1 條邊， 而「最多用 r 條邊的最短路徑」正好就是 Bellman-Ford 第 r 輪算出來的東西。 那個看起來很麻煩的限制就是迴圈計數器。

def find_cheapest_price(n, flights, src, dst, k):
    dist = [INF] * n
    dist[src] = 0
    for _ in range(k + 1):
        prev = dist[:]                      # snapshot of the previous round
        for u, v, w in flights:
            if prev[u] + w < dist[v]:
                dist[v] = prev[u] + w
    return dist[dst] if dist[dst] < INF else -1

整題的重量壓在一行上：prev = dist[:]。每一輪都必須拿上一輪的值來放鬆， 因為輪數在數的是邊數。原地放鬆的話，一輪之內就可能串成 0 -> 1 -> 2 -> 3， 因為 dist[1] 被寫進去之後，馬上就被清單裡下一個航班讀走。

在標準測資、k = 1 的情況下，正確答案是 700（0 -> 1 -> 3）。 原地版本會回答 400，那是 0 -> 1 -> 2 -> 3 的價格——轉了兩次機，比允許的多一次。 它不會當掉、不會逾時，而且錯的那個數字還比較小，看起來像更好的解。 我看過這一行決定一場面試的結果。

更一般的教訓跟「狀態」有關。只要限制條件開始數東西，節點本身就不再是一個狀態了， 狀態是 (節點, 已用邊數)。Bellman-Ford 剛好把第二個分量放在它的迴圈變數裡， 所以它才會跟這題契合得這麼漂亮。

什麼時候用哪個

情境                    演算法
----------------------  ----------------------
非負權重、單一起點      Dijkstra，O(E log V)
任意權重、單一起點      Bellman-Ford，O(VE)
同上，但實務上想快一點  SPFA，最壞情況相同
所有點對、稠密圖        Floyd-Warshall，O(V^3)
限制條件在數邊數／步數  Bellman-Ford，一步一輪

這個系列一再出現的模式是：演算法的速度通常是拿一個假設換來的， 而那個假設通常在壞掉之前都是隱形的。Day 16 用「權重非負」換到 O(E log V)， 今天我們付出 O(VE) 把它買回來。

負權重一點都不冷門。只要一條邊代表的是報酬而不是成本，它就會出現—— 這正好是後面 value iteration 與 Q-learning 背後那組 Bellman equations 的場景， 到時候這個 relaxation 迴圈幾乎會原封不動地再出現一次。
