100 Days of Python - day 52

Attention 就是一個加權平均。整個模型就這件事：每個 query 位置對每個 key 位置算一個分數，把分數變成加總為 1 的權重，再用這些權重去平均 value 向量。四行 numpy。

難的地方全部不在那條式子，而在「怎麼把這個平均算出來，又不要真的把它要平均的那個東西生出來」。context 長到 131,072 個 token 時，光是一層的分數矩陣在 fp16 下就是 1,024 GB，那不是一個你配置得出來的數字；而讓你不用重算過去的 KV cache，同樣的 context 下用一般的 multi-head attention 是 64.0 GB，用 MLA 是 4.5 GB。今天先把 attention 實作出來，看它兩種不會報錯的壞法，然後看所有推論系統都會對它做的四個改動：FlashAttention、PagedAttention、MQA/GQA/MLA 這一家，以及 delta rule 這種線性 attention。

Day 51 把文字變成 token id，今天是模型拿到這些 id 之後做的事。

一張圖看懂 attention 在做什麼

attention(Q, K, V) = softmax(Q K^T / sqrt(d)) V

從右往左讀，它就是一個對 V 的加權平均；從左往右讀，它是四個步驟，而圖上每一步都用真實數字跑過一次（4 個 query、6 個 key、head dimension 8）。

每一對位置一個分數。 第 0 列的 query 跟六個 key 各做一次內積，得到六個數字：+0.20、+0.03、−0.26、+0.69、+1.32、−0.12。內積在兩個向量方向一致時比較大，所以一個分數講的是「這個 query 有多想讀那個位置」。每一對位置都會有一個，這就是本文後面整篇在算的那個 n x m 矩陣。

除以 sqrt(d)。 一個分數是 d 個乘積的和，所以 head 越寬它散得越開。除以 sqrt(d) 可以讓數字不管 d 多大都維持在大約單位尺度——後面量到的是：不除的話，4096 寬的 head 平均會把 0.9688 的權重壓在單一個 key 上。

softmax 把分數變成權重。 取指數再除以總和，六個權重變成 0.1269、0.1065、0.0799、0.2059、0.3886、0.0923。它們非負、加總剛好是 1.00，而分數最高的位置 4 拿到最多。

乘上 V。 輸出那一列就是用這些權重去加權六列 value：out = 0.1269 v0 + 0.1065 v1 + … + 0.0923 v5。因為權重非負而且加總為 1，輸出是 value 的凸組合，永遠跑不出它們的範圍。attention 生不出新的值，它只能決定每一個既有的值要用多少。

整個模型就這樣。Q、K、V 本身只是輸入的線性投影，mask 只是多一行，而這篇文章後面全部的內容，都是在講「怎麼把這個平均算出來，又不要真的把它要平均的那個矩陣生出來」。

一個加權平均

def attention(Q, K, V, mask=None, scale=None):
    d = Q.shape[-1]
    scores = Q @ K.T / (scale if scale is not None else math.sqrt(d))
    if mask is not None:
        scores = np.where(mask, scores, -np.inf)
    w = softmax(scores, axis=-1)
    return w @ V, w

Q 是 (n, d)、K 和 V 是 (m, d)，分數矩陣是 (n, m)：每一對位置一個數字。那個「每一對」就是二次方成本的來源，也是這篇文章後面全部內容存在的理由。

4 個 query、6 個 key、head dimension 8 時，權重矩陣是 (4, 6)，每一列加總都是 1。第 0 列是 [0.1269 0.1065 0.0799 0.2059 0.3886 0.0923]。因為每一列都是一組非負、加總為 1 的數，所以每一列輸出都是 value 那幾列的凸組合，永遠跑不出 V 的範圍：V 的範圍是 [-0.634 -1.504 -1.052] 到 [1.107 0.519 1.721]，輸出的範圍是 [0.332 -0.667 -0.07] 到 [0.42 -0.24 0.112]。attention 沒辦法生出一個新的值，它只能決定每一個既有的值要用多少。

第一個不會報錯的壞法：exp() 吃到大數

課本上的 softmax 是 exp(x) / sum(exp(x))。float32 最大裝到 3.403e+38，而 exp(89) 就已經是 inf；float16 最大 65504，exp(12) 就已經是 inf。所以 softmax_naive([1000, 1001, 999]) 回傳 [nan nan nan]：inf 除以 inf。

修法只有一行，而且它是精確的不是近似：對任何常數 c，softmax(x) 都等於 softmax(x - c)，因為 c 在分子和分母互相抵消。取 c = max(x) 讓最大的那個指數剛好是 exp(0) = 1，就不可能溢位：

def softmax(x, axis=-1):
    x = np.asarray(x, dtype=float)
    m = np.max(x, axis=axis, keepdims=True)
    e = np.exp(x - m)
    return e / e.sum(axis=axis, keepdims=True)

同一組輸入現在給 [0.2447 0.6652 0.09]。1000 這種 logit 聽起來很荒謬，直到你想起來一個分數是兩個 d 維向量的內積——而且在 fp16 裡你只需要 12。

為什麼要除以 sqrt(d)，用量的

一個分數是 d 個乘積的和。輸入變異數為 1 時，這個和的標準差本來就隨著 sqrt(d) 長大，所以 head 越寬 logit 散得越開，而 softmax 碰到散得很開的 logit 就會塌成一個 argmax。

d     原始分數的標準差  sqrt(d)  最大權重（未縮放）  除過 sqrt(d)
----  ----------------  -------  ------------------  ------------
8     2.846             2.83     0.3221              0.0437
64    7.911             8.00     0.7067              0.0404
512   22.563            22.63    0.9048              0.0423
4096  64.109            64.00    0.9688              0.0428

每一個寬度上量到的標準差都貼著 sqrt(d)，誤差大約在百分之一（最差的是 d = 64，7.911 對 8.00）。不除的話，4096 寬的 head 平均把 0.9688 的權重壓在一個 key 上：那就是 argmax，而 argmax 幾乎不會把梯度傳給其他 key。除以 sqrt(d) 之後，不管 d 多大 logit 都維持在大約單位尺度，寬度差了 512 倍、平均最大權重都還在 0.04 附近。

第二個不會報錯的壞法：mask 放在 softmax 之後

causal 語言模型必須擋住位置 i 去讀位置 j > i。正確做法是在 softmax 之前把那些分數設成 -inf：exp(-inf) 是 0，那些 key 拿到的權重剛好是 0，而每一列還是加總為 1。錯的做法——在 diff 裡看起來一模一樣——是先算 softmax 再把未來那幾格歸零。

row sums, masked before softmax: [1. 1. 1. 1. 1. 1.]
row sums, masked after  softmax: [0.0504 0.5048 0.0618 0.9274 0.826  1.    ]

第 0 列只看得到自己，它那唯一一個權重應該是 1.0。先 softmax 再歸零的版本給 0.0504：每個比較早的位置都被「它不准看的那部分未來」等比例縮小，輸出也就等比例地更靠近零。沒有例外、沒有 nan、形狀全對，loss 照樣往下掉——只是模型訓練的時候，前面的位置被一個隨機的倍率壓著。

FlashAttention：同一個數字，一趟掃完，不生出矩陣

天真的寫法必須把整個 (n, m) 分數矩陣生出來，因為 softmax 要用到每一列的最大值和總和，而這兩個東西都要看完整列才有。online softmax 說：不一定，只要你願意回頭修正已經算好的部分。

一塊一塊地走 key，每個 query 列只帶兩個數字——目前看過的最大分數，以及 exp(分數 - 那個最大值) 的滾動總和。某一塊出現更大的分數時，把已經累積的東西乘上 exp(舊max - 新max) 再繼續。那個重新縮放就是全部的訣竅：

s_blk = Q @ K[s:e].T / math.sqrt(d)          # 分數矩陣的一塊
new_max = np.maximum(run_max, np.max(s_blk, axis=-1))
alpha = np.exp(run_max - new_max)            # 把已經累積的補正到新的最大值
p = np.exp(s_blk - new_max[:, None])
run_sum = run_sum * alpha + p.sum(axis=-1)
out = out * alpha[:, None] + p @ V[s:e]
run_max = new_max

（檔案裡多兩個 np.where 是為了「整列的 key 都被 mask 掉」那種列，不然 running max 會留著 -inf）

每塊大小  與完整矩陣的最大絕對差
--------  ----------------------
1         6.661e-16
8         3.886e-16
32        3.608e-16
128       3.886e-16
256       4.996e-16

每一個 block size 的差都是浮點數最後一位的雜訊。這件事比看起來重要：FlashAttention 是同一個和的精確改寫，不是它的近似，所以打開它改變的是記憶體和速度、不是模型。沒有一欄「準確度」需要檢查。

二次方那一項寄來的帳單

分數矩陣每一對位置一格，每個 head、每一層各一份。fp16、32 個 head：

context  一層的分數矩陣  32 層
-------  --------------  ----------
1,024    0.06 GB         2.0 GB
4,096    1.00 GB         32.0 GB
16,384   16.00 GB        512.0 GB
131,072  1024.00 GB      32768.0 GB

context 乘 4，這個數字乘 16。131,072 時一層就是 1,024 GB，而 FlashAttention 真正的貢獻是它從頭到尾沒有配置它：一次只拿一塊，所以記憶體變成跟 context 成線性，而算術仍然是二次方。二次方的「工作量」沒有消失，消失的只有二次方的「儲存」。

PagedAttention：KV cache 其實是個記憶體配置器問題

生成的時候你不會重算過去，而是把看過的每個 token 的 K 和 V 留著。連續配置的 cache 必須按「這條序列可能長到多長」保留，因為一旦發出去就搬不動了。8 條長度 [12, 300, 48, 900, 7, 2048, 64, 130] 的序列，每條都可能長到 4,096：

one contiguous block per sequence: 32,768 slots, 3,509 used, 89.3% wasted
pages of   16:   3,552 slots, 3,509 used,  1.2% wasted (222 pages)
pages of   64:   3,776 slots, 3,509 used,  7.1% wasted (59 pages)
pages of  256:   4,864 slots, 3,509 used, 27.9% wasted (19 pages)

改成邊長邊發固定大小的頁，剩下的浪費就只有每條序列最後一頁的尾巴——每條最多 page_size - 1 格，不管序列長到多長。所以浪費從 89.3% 掉到 1.2%，再隨著頁變大爬回 27.9%：頁大小是在「尾巴的浪費」和「頁表的大小」之間選。

代價是 attention 不能再把 K 和 V 當成一塊平坦的陣列讀，要先查頁表。這就是作業系統對記憶體做的同一件事、同一個理由，而且順便給了同一個好處：兩條共用同一段 prompt 的序列可以指向同一批前綴頁，不用各留一份。

MHA、MQA、GQA、MLA：「到底什麼非 cache 不可」的四個答案

分頁解決的是浪費，它不會改變一個 token 本身要多少。32 層、32 個 query head、head dimension 128、fp16：

layout                       bytes/token  KB   128k context  vs MHA
---------------------------  -----------  ---  ------------  ------
MHA（32 個 kv head）         524,288      512  64.0 GB       1.0x
GQA（8 個 kv head）          131,072      128  16.0 GB       4.0x
MLA（512 latent + 64 rope）  36,864       36   4.5 GB        14.2x
MQA（1 個 kv head）          16,384       16   2.0 GB        32.0x

有趣的是「各自放棄了什麼」那一欄。MQA 讓 32 個 query head 讀同一份 K 和 V，head 就失去了各自注意不同東西的能力；GQA 是同一個取捨但以四個一組做，所以它是現在最常見的預設。MLA 每個 token 只留一個低秩的 latent 向量，讀的時候再從它重建出每個 head 的 K 和 V，所以 head 仍然各自不同、cache 還是小 14.2 倍——代價是讀取時多出來的算術，以及一條專門給位置資訊走的小路，因為 rotary embedding 沒辦法被摺進那個 latent 裡還活著。

這四個都還是隨 context 長大，因為 cache 是「每個 token 一份」。下一節是不會長大的那一家。

delta rule：一個拿來寫的狀態，不是一個拿來疊加的 cache

softmax attention 把每個 key 和 value 都留著，每一步再全部重讀一次。這正是它精確的原因，也正是 cache 會長大的原因。delta rule 這一層只留一個 d x d 的矩陣，就地修改它：

out[t] = S @ k                                    # 讀
S = S - b * np.outer(S @ k, k) + b * np.outer(V[t], k)   # 先擦掉，再寫進去

也就是把 S <- S (I - beta k k^T) + beta v k^T 的乘積展開。第一項把 S 目前對 k 的關聯擦掉，第二項把 v 寫到那個位置。讀就是一次矩陣乘向量——真正的一層是用它自己的 query 投影讀，o = S @ q；這個檔案拿 key 本身去探，因為它要量的是「存進去的東西還在不在」。32 層加起來的狀態是 32 MB，而且 context 是 1,000 個 token 還是 1,000,000 個，它都還是 32 MB。

剩下的問題是「裝得下多少」。把互相正交的 key-value 對寫進一個 16 x 16 的狀態再全部讀回來：

寫進去的對數  最差的回想誤差  被蓋掉的關聯數
------------  --------------  --------------
8             1.00e-12        0
16            1.00e-12        0
17            1.33e+00        1
24            1.69e+00        8
32            1.87e+00        16

16 個剛好裝滿，因為 16 維空間裡最多只有 16 個互相正交的方向——前兩列那個 1e-12 是這個檔案在正規化 key 時加的 epsilon，不是互相干擾。第 17 個剛好蓋掉其中一個，32 個蓋掉 16 個。最新寫進去的那個永遠是完美的——它的誤差是 1.8e-12——被犧牲的是舊的。而且這還是最好的情況：換成一般的隨機 key 而不是正交的，8 對寫進同一個狀態就已經有 1.66 的最差誤差，因為每一次寫入都會把已經在裡面的抹糊一點。

所以這個取捨不是「線性 attention 比較差」，而是：記憶體是常數，回想有上限。gated 的那一支加上遺忘係數，讓舊的關聯是慢慢衰減而不是撐到被蓋掉，這個上限就表現得好一些：Gated DeltaNet 是每個 head 一個純量衰減，Kimi 的 KDA 再細到每個通道一個（對角的 gate）。狀態仍然是一個固定大小的矩陣。這也是為什麼實務上這些層是跟少數幾層完整 attention 交錯使用而不是取代它：完整的那幾層負責精確的長距離回想，線性的那些層用每個 token 固定的成本扛其他全部。

LeetCode 239 - Sliding Window Maximum（滑動視窗最大值）

題目在問什麼。 給你一個陣列和一個視窗寬度 k。視窗從最左邊開始，一次往右移一格，一直到最右邊。請回報視窗在每一個位置時，裡面的最大值。

輸入輸出。 輸入整數陣列 nums 與整數 k，回傳一個有 len(nums) - k + 1 個元素的 list，第 i 個是 nums[i:i+k] 的最大值。

範例。 nums = [1, 3, -1, -3, 5, 3, 6, 7]、k = 3 的答案是 [3, 3, 5, 5, 6, 7]。第一個視窗 [1, 3, -1] 最大是 3；第二個 [3, -1, -3] 還是 3；接著 [-1, -3, 5] 把 5 帶進來，5 再撐一個視窗就被 6、然後 7 接手。

限制。 最多 100,000 個元素、1 <= k <= len(nums)。每個視窗重掃一次是 O(n*k)，上限那端是 10^10 次運算，過不了；而對視窗維護一個 heap 要做到 O(n log k) 的前提是你能刪掉「剛離開視窗的那個元素」，普通的二元 heap 沒有額外記帳做不到。這題要的是 O(n)。

維護一個 deque，裡面放的是 index，對應的值由大到小。新的值進來時，尾巴上所有比它小的都永遠出局了：新來的又大又新，所以在任何還包含它們的視窗裡，新來的都是更好的答案。deque 的頭就是目前視窗的最大值，而它只在「按 index 掉出視窗」時才被丟掉。

class Solution:
    def maxSlidingWindow(self, nums: list[int], k: int) -> list[int]:
        from collections import deque
        dq, out = deque(), []
        for i, v in enumerate(nums):
            while dq and nums[dq[-1]] <= v:
                dq.pop()
            dq.append(i)
            if dq[0] <= i - k:
                dq.popleft()
            if i >= k - 1:
                out.append(nums[dq[0]])
        return out

它看起來像雙層迴圈，但每個 index 只被推進去一次、彈出來一次，所以整趟是 O(n)，狀態是 O(k)。那個滾動最大值就是 FlashAttention 那一節：online softmax 帶的是一個數字而不是整列，而且每次那個數字變了就把已經算好的補正一次。

LeetCode 703 - Kth Largest Element in a Stream（資料流中的第 k 大元素）

題目在問什麼。 寫一個類別，建構時給它 k 和一串起始數字，之後每加進一個新數字，就回答「到目前為止第 k 大的是多少」。

輸入輸出。 KthLargest(k, nums) 建構；add(val) 加入一個數字，回傳包含 val 在內、看過的所有數字中第 k 大的那個。

範例。 KthLargest(3, [4, 5, 8, 2]) 之後依序加入 3、5、10、9、4，回傳 [4, 5, 5, 8, 8]。加入 3 之後所有值是 2, 3, 4, 5, 8，第三大是 4；加入 10 之後變成 5，因為前三名現在是 10、8、5。

限制。 add 最多呼叫 10^4 次，而且保證查詢時至少已經有 k 個元素。這題的重點在記憶體：它不希望你把整串資料留著。

維護一個剛好 k 個元素的 min-heap。它的堆頂就是目前的第 k 大，而任何比堆頂小的值一進來就可以直接丟掉。

class KthLargest:
    def __init__(self, k: int, nums: list[int]):
        import heapq
        self.k = k
        self.heap = list(nums)
        heapq.heapify(self.heap)
        while len(self.heap) > k:
            heapq.heappop(self.heap)

    def add(self, val: int) -> int:
        import heapq
        if len(self.heap) < self.k:
            heapq.heappush(self.heap, val)
        elif val > self.heap[0]:
            heapq.heapreplace(self.heap, val)
        return self.heap[0]

陷阱是「用哪一種 heap」。把全部東西放進一個 max-heap 也答得出來，記憶體 O(n)、每次呼叫 O(k log n)——它會通過測試，而它是對這個問題的錯誤答案。size-k 的 min-heap 才是那個「記憶體跟已經流過多少無關」的版本。

這些東西之後會用在哪

今天每一個東西做的都是同一件事：掃過一串你存不下的資料，身上只帶一份有上限的狀態，而那份狀態必須夠用。FlashAttention 把它限制在每個 query 列兩個數字，而且保持精確；delta rule 把它限制在一個矩陣，放棄精確。LeetCode 239 限制在一個 deque、703 限制在一個 size-k 的 heap。哪一個上限是對的，完全看你願意失去什麼。

分頁那一節也是作業系統那套東西回來的地方：頁、頁表、內部碎片、copy-on-write 共用，只是這次套在張量而不是行程的位址空間上。而 MLA 的那個低秩 latent 就是 Day 49 的 Eckart-Young 近似，只是這次拿來當儲存格式而不是拿來畫圖。
